# dashboard/assets — 마을 지도 이미지

이 폴더의 이미지는 **소스 자산**이다. CI 가 `dashboard/` 전체를 `_site/` 로 복사하므로
페이지에서는 `assets/<파일명>` 상대경로로 서빙된다(외부 요청 0 · CDN 금지 규약).

## 필요한 파일 2개

| 파일명 | 내용 |
|---|---|
| `village-day.webp` | 마을 지도 — 낮 (라이트 테마) |
| `village-night.webp` | 마을 지도 — 밤 (다크 테마) |

**확장자는 `.webp` → `.png` → `.jpg` 순으로 찾는다**(`VILLAGE_EXTS` in `app.js`). 변환 도구가
없으면 Gemini 가 준 **PNG 를 그대로 `village-day.png`·`village-night.png` 로 올려도 뜬다.**
다만 webp 가 아니면 앞 후보를 찾다가 콘솔에 404 가 한 줄 남고 파일이 서너 배 무겁다 —
이 저장소는 아직 LFS 가 아니라 이력이 그만큼 불어난다. 여유가 되면 webp 로 올릴 것.

**두 장은 구도·건물 위치가 동일해야 한다.** 클릭 영역(`VILLAGE_ZONES` in `app.js`)이
비율 좌표로 두 장에 공통 적용되므로, 배치가 어긋나면 밤 테마에서 클릭이 빗나간다.

**가로가 긴 이미지를 쓸 것**(16:9 안팎). 지도는 화면 폭에 맞춰 늘어나고 높이는 비율대로
따라가므로, 세로로 긴 지도를 넣으면 마을 화면이 다시 길어진다 — 스크롤을 줄이려고 만든
구조를 스스로 무너뜨리는 셈이다.

## 넣는 법

1. Gemini 로 생성한 PNG 를 받는다.
2. WEBP 로 변환·압축한다 (저장소가 아직 LFS 가 아니라 이력이 그대로 불어난다):
   ```bash
   # 예: 폭 1600px, 품질 82 — 지도 한 장이 대략 200~400KB 면 충분하다
   cwebp -q 82 -resize 1600 0 village-day.png  -o dashboard/assets/village-day.webp
   cwebp -q 82 -resize 1600 0 village-night.png -o dashboard/assets/village-night.webp
   ```
3. 커밋한다. 파일이 없으면 마을 화면은 안내 문구를 띄우고, 나머지 대시보드는 정상 동작한다.

## 넣지 말 것

- **실제 공식 마크**(우정사업본부 제비 CI·정부 태극 상징)를 이 공개 저장소에 커밋하지 말 것.
  관문의 로고 자리는 지금 편지 글리프(`index.html` 의 `#gate-emblem`) 하나뿐이다. 마크를
  넣는 것은 **접근제어 호스팅으로 옮기고 기관 확인을 받은 뒤**의 일이다(`docs/HANDOVER.md` §3.3).
- 이미지에 **글자를 굽지 말 것**. 라벨은 전부 코드가 얹는다(선명·수정·다국어·접근성).

## 전환 영상 — 테마 토글에서 밤이 내리는(걷히는) 연출

| 파일명 | 내용 |
|---|---|
| `village-dusk.mp4` | 낮 → 밤 전환 (라이트→다크 토글 때 재생) |
| `village-dawn.mp4` | 밤 → 낮 (같은 영상의 역재생 인코딩본) |

**정지 지도 두 장은 이 영상의 첫/끝 프레임에서 뽑은 것이다** (2026-08-03, 사용자 Gemini
생성 영상 기반). 그래서 "영상 첫 프레임 = 낮 지도, 끝 프레임 = 밤 지도"가 항상 성립하고,
테마 토글은 그 사이를 재생(2.5배속, 약 4초)으로 메운다. 루프가 아니므로 이음새 문제가 없다.

- 파일이 없거나 로딩이 늦으면(700ms) 연출 없이 즉시 전환된다 — 영상은 장식이지 필수가 아니다.
- 접근성 설정(움직임 줄이기) 사용자는 영상 없이 즉시 전환된다.
- **영상을 교체하려면 정지 지도 2장도 그 영상에서 다시 뽑아야 하고**(첫/끝 프레임),
  클릭 좌표(`VILLAGE_ZONES`)와 SVG 모션 좌표(물길·도로)도 다시 맞춰야 하며, **아래 상시
  루프 4개도 그 영상에서 다시 잘라야 한다.** 구도가 바뀌면 전부 어긋난다 — 교체는 세트로만.

## 상시 앰비언트 루프 — 마을이 "실제로 움직이는" 배경 영상 (2026-08-03 2차)

스틸에 구워진 새·구름·행인이 SVG 모션과 나란히 정지해 있는 모순("어떤 새는 움직이고
어떤 새는 얼어 있다")을 없애기 위해, **같은 전환 영상에서 테마별 무이음새 루프를 잘라**
지도 스틸 위에 상시 재생한다(`app.js` `mountVillageVideo`, muted·loop·playsinline).

원본은 24fps 240프레임(10초)이다. 아래 표의 **프레임 번호가 정본**이고, 초 단위는 참고값이다.

| 파일명 | 프레임 수 | 구성 | 첫 프레임 |
|---|---|---|---|
| `village-day-loop.webm/.mp4` | 117 (4.88초) | 원본 `[0,141)` 중 앞뒤 24프레임을 α블렌드해 봉합 후 24프레임 회전 | 원본 f24 |
| `village-night-loop.webm/.mp4` | 94 (3.92초) | `[239, 238..193, 192, 193..238]` 팔린드롬 | 원본 f239 |

**원본 10초를 통째로 `<video loop>` 에 걸면 안 되는 이유(실측):** 원본은 루프가 아니라
낮→밤 전환이다 — 첫↔끝 프레임 평균절대차(MAD, 그레이) **55.35** (RGB 48.55) 인 반면 첫↔중간은
4.60, 인접 프레임은 평균 0.38. 그대로 돌리면 10초마다 밤→낮이 튀고(1차 영상 반려 사유였던
이음새의 최악형), 라이트/다크 테마와 화면의 낮/밤이 어긋나며, 움직임 규약의
"자동 낮밤순환 없음"에도 걸린다.

**판정 기준선 — 이 수치들과 비교해서 읽을 것:** 낮 안정 구간의 통상 인접 프레임 차이는
평균 0.38 / 최대 1.27 이고, 서로 다른 인코딩 간 "같은 그림"의 바닥값은 약 2.0~2.3 이다
(전환 영상 끝 프레임 ↔ 원본 f239 = 2.04, 역재생본 끝 ↔ 원본 f0 = 2.34). 즉 **2 부근이면
무이음, 1.3 이하면 통상 프레임 한 스텝**이다.

| 실측 | day webm | day mp4 | night webm | night mp4 |
|---|---|---|---|---|
| 루프 이음새(끝↔첫) | **0.23** | 1.55 | **0.14** | 0.82 |
| 전환 연출 → 루프 핸드오프 | 3.84 | 3.89 | **2.33** | 2.37 |
| 용량 | 393,766B | 922,110B | 218,350B | 530,278B |

- **밤은 완전 무이음이다** — 루프 첫 프레임이 전환 영상의 끝 프레임(=밤 스틸)과 같은 그림이라
  핸드오프 2.33 이 바닥값 2.04 와 사실상 같다.
- **낮은 구조적으로 1초를 건너뛴다**(핸드오프 3.84 vs 바닥 2.34). 크로스페이드 루프는 봉합에
  쓴 24프레임만큼 뒤에서 시작할 수밖에 없기 때문이다. f0 에서 시작하는 **하드컷** 루프도
  찾아봤지만 최선의 이음새가 3.69 로 통상 스텝(1.27)의 3배라 더 나쁘다 — 구름·새가 한 방향으로
  흐르는 그림이라 되돌아오는 프레임이 없다. 그래서 `.village-video[data-idle]` 에 **0.45초
  페이드인**을 걸어 이 도약을 덮는다(`style.css`, `app.js` 의 `is-on`).
- 낮은 크로스페이드(새·행인 같은 방향성 모션은 역재생하면 어색), 밤은 팔린드롬(별·창불빛
  깜빡임은 무방향이라 역재생이 보이지 않고, 꼬리가 2초뿐이라 두 배로 늘린다).
- webm(VP9)이 정본이고 mp4(H.264)는 VP9 를 못 읽는 브라우저(구형 Safari 등)용 폴백이다.
  **mp4 는 원본이 아니라 webm 정본에서 다시 인코딩한다**(`-crf 18`) — 두 경로가 같은 그림을
  보여야 하고, 실측상 원본 PNG 에서 뜬 것보다 이음새(1.55 vs 2.26)·정본 일치도(0.62 vs 1.25)·
  용량(922KB vs 1,043KB)이 모두 낫다.
- reduced-motion 사용자에게는 마운트하지 않고(JS+CSS 이중 차단), 파일이 없거나 재생이 거부되면
  조용히 스틸 + SVG 모션으로 물러난다. 재생 중에는 SVG 모션이 꺼진다(`.has-video`, 중복 방지).
- 재생성 레시피 — 프레임 단위 조립이라 ffmpeg 필터 한 줄로는 안 되고 PNG 시퀀스를 거친다:
  ```python
  # 1) 원본을 RGB 프레임으로 디코드 (24fps, 1280x720)
  # 2) 낮: main = src[24..116];  blend[k] = (1-k/23)*src[117+k] + (k/23)*src[k]  (k=0..23)
  #        day = main + blend            -> 117프레임, 첫 프레임 src[24], 끝 src[23] → 첫과 인접
  #    밤: night = [src[239]] + src[238..193] + [src[192]] + src[193..238]   -> 94프레임
  # 3) PNG 로 쓴 뒤 인코딩
  ```
  ```bash
  # 정본(VP9)
  ffmpeg -framerate 24 -i %04d.png -an -c:v libvpx-vp9 -b:v 0 -crf 34 -row-mt 1 \
    -pix_fmt yuv420p village-day-loop.webm
  # 폴백(H.264) — 원본이 아니라 위 webm 에서
  ffmpeg -i village-day-loop.webm -an -c:v libx264 -crf 18 -preset slow \
    -pix_fmt yuv420p -movflags +faststart village-day-loop.mp4
  ```
  구간 경계(낮 141프레임·밤 192프레임)는 프레임 차분으로 실측한 값이다 — 전환이 시작되는
  프레임은 f145 부근이고 f151 에서 변화가 가장 크다. 다른 영상으로 갈아끼우면 **경계부터
  다시 재라.** 테스트가 파일 존재·컨테이너 매직바이트·용량(1.5MB/파일)을 강제한다.

## 알려진 특이점

- 언덕 위 탑은 **밤에만 서서히 나타난다** — 원본 영상의 연출이라 그대로 두었고, 클릭
  대상이 아니다. 옛 지도의 성채·망루는 이 지도에 없어서 리스크→종탑(교회), 이벤트→여관으로
  재배정했다.
