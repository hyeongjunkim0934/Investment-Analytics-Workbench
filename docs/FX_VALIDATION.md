# 환율 A/C/D 공통 시점 검증

`pipeline/fx_validation.py`는 기존 환율전망의 전체 일별 이력과 모형 C의 과거 예측행을
받아 A/C/D 및 단순 기준을 같은 기준일·목표일·실현환율에서 비교한다. 산출물은
`fx.json.validation`이며 `fx_validation_v1` 계약을 사용한다. 학습용 원수익률과 모의경로를
새로 게시하지 않는다. 기존 모델의 실시간 예측이나 저장된 사용자 전망을 변경하지 않는다.

## 계산 범위

호출은 `build(outlook, model_c, warn=None, max_origins=36, path_count=1000)`이다.
오류·입력 부족 시 `active:false`와 이유를 반환한다. 정상 산출물도 지평별 공통 평가행이
없으면 해당 지평만 비활성화한다. B는 별도 월간 입력·학습 아티팩트 경로를 사용하므로
이번 공통 비교에서 제외한다. B 아티팩트의 존재 여부나 품질을 이 제외 사유로 판단하지 않는다.

| 항목 | 계약 |
|---|---|
| 지평 | 1·3·6·9·12개월 |
| 기준일·목표일 | C의 정확한 월말 마지막 평일 관측일 |
| 원천 | outlook과 C가 같은 원천이어야 하며 기준·실현환율도 일치해야 함 |
| 결측 | 목표일의 실제 관측이 없으면 제외; 보간·앞채움 없음 |
| 기준일 선택 | 성과 계산 전 후보 기준일 합집합에서 최근 36개 날짜 선택 |
| 계산 한도 | 전 지평 합계 최대 36회 A/D 재추정; 시뮬레이션 각 1,000경로 |
| 난수 | 고정 PCG64 seed에 기준일을 결합; 전체 표본 길이·반복 순서와 무관 |
| 수치 범위 | 환율 수준 0 초과·10의150승 이하; 제곱손실의 유한 계산 범위를 위한 방어 조건 |

기준일 선택은 **모형 적합 전에** 고정한다. A가 수렴하지 않은 날짜를 다른 날짜로 채우지
않고 제외 이유를 기록한다. 따라서 공통 표본은 A가 적합 가능한 시점에 조건부이며,
실패가 많은 국면을 포함한 전체 운용 성과로 해석하지 않는다. 긴 지평은 아직 실현되지
않은 목표일 때문에 단기 지평보다 평가행 수가 작을 수 있다. `n_candidates`,
`n_selected`, `n_common`, 실제 기준일·목표일 범위를 함께 확인한다.

## 정보시점과 달력

C는 기존 엔진의 당시 실현된 라벨만 학습한 과거 예측행을 재사용한다. A는 각 기준일까지의
유효 일별 수익률(최소 756·최대 2,520개)을 다시 적합한다. 장기 공백 수익률은 제외하고
독립 필터 구간으로 처리한다. D는 각 기준일 이전 마지막 장기 공백 이후 연속구간에서
최소 504·최대 2,520개 수익률을 사용한다. D의 과거 백테스트를 재귀 실행하지 않는다.
상수·EWMA 분산 기준도 D와 같은 학습 수익률을 사용한다.

각 목표일까지 A/D가 전개하는 step 수는 **기준일 다음 날부터 목표일까지의 월~금 개수**다.
기준일에 미리 알 수 있는 달력으로 결정하며 미래의 실제 관측 개수를 사용하지 않는다.
별도 휴일 달력은 없다. 따라서 이 검증의 A/D 달력 변환은 기존 상세 화면의
`21 steps × 개월`과 다르다. 공통 달력 목표에서 재계산한 예측의 평가이며, 기존 상세
화면의 21-step 구간에 대한 정확한 실현 포함률이라고 표시하지 않는다.

날짜가 늘거나 미래 값이 바뀌어도 같은 과거 기준일의 학습 입력·난수 경로 앞부분은
변하지 않는다. 다만 원본 값이 사후 수정된 최신 데이터셋을 사용하므로 실시간 빈티지
백테스트가 아니다. 월간 평가행의 장기 지평은 겹치며 독립 표본수로 간주하지 않는다.

## 비교값과 성과 지표

점 비교는 다음 값을 같은 행에서 계산한다.

| 키 | 점예측 |
|---|---|
| `a` | A 모의 환율 수준의 중앙값 |
| `c` | 기존 C의 기하적 로그예측 중심 |
| `d` | 기준환율: 평균 로그변화 0·대칭 충격 분포의 이론 중앙값 |
| `rw` | 기준환율 |
| `equal_ac_rw` | A·C·RW 수준 예측의 1/3씩 단순평균 |
| `shrink_ac_rw` | A 25%·C 25%·RW 50% 고정 평균 |

C 자체의 기존 50% RW 축소는 그대로 포함된다. 위 결합은 추가 비교 기준이며 가중치를
성과자료로 추정하지 않는다. D의 수준 산술평균은 Jensen 효과와 모의오차를 포함하므로
방향 신호로 비교하지 않는다. A/D 산술평균은 행의 별도 필드에 보관한다. 결합모형에
구간이 있는 것처럼 점예측 평균으로 불확실성 구간을 만들지 않는다.

MAE·RMSE는 원/달러 수준 오차로 계산한다. Theil U는 같은 행 RW의 RMSE로 나눈 값이며
RW 오차가 0이면 정의하지 않는다. D와 RW의 점예측은 정의상 같으므로 점성과의 차이를
기대하지 않는다. D의 주된 비교 대상은 분산·구간 지표다.

68%·95% 구간은 A/D의 조건부 모의 분위수, C의 당시 실현오차에 기반한 기존 구간,
상수·EWMA의 평균로그변화 0 정규 구간을 사용한다. C의 교정 표본이 부족한 행은 모든
모형의 해당 구간통계에서 함께 제외한다. 점비교 N과 구간비교 N을 별도로 게시한다.

구간 점수는 폭에 초과 손실을 더하는 Winkler 점수다. 실제값이 하단보다 작으면
차이에 2/α를 곱하고, 상단보다 크면 초과 차이에 2/α를 곱해 구간 폭에 더한다.
α는 68% 구간에서 0.32, 95% 구간에서 0.05다. 단위는 원/달러이며 작을수록 좋다.
구간을 무작정 넓혀 포함률만 높이는 선택을 구별할 수 있다.

D·상수·EWMA의 분산비교는 같은 누적 로그변화 제곱을 실현분산의 proxy로 사용한다.
이는 분산을 직접 관측한 값이 아니다. 예측값은 같은 목표일까지의 누적 로그분산이다.
D는 조건부 분산의 기대경로를 합산하고, 상수와 EWMA는 기준일의 일별 분산에
사전에 정한 step 수를 곱한다. EWMA decay는 기존 D와 같은 0.94다.

QLIKE는 예측분산의 로그에 실현 proxy를 예측분산으로 나눈 값을 더해 평균한다.
음수 점수가 가능하고 작을수록 좋다. 점수가 양수인지보다 같은 표본에서의 차이가
중요하다. 평균로그변화 0 가정이 맞지 않으면 terminal 제곱수익 proxy에 방향 성분도
섞일 수 있다. 분산 추정의 절대 정확도나 독립 검증으로 과장하지 않는다.

## JSON 계약

상위 필드는 `schema/active/reason/asof/source/pair/unit/config/excluded_models/selected_origins/horizons`다.
각 지평은 `horizon_months/active/reason/n_candidates/n_selected/n_common/rows/metrics/excluded`를 가진다.

- `rows`: 기준일·목표일·기준환율·실현환율·step 수·학습표본수·점예측·산술평균·구간·분산.
- `metrics.point[key]`: `n`, `mae`, `rmse`, `theil_u_rw`.
- `metrics.interval["68" 또는 "95"]`: 공통 `sample`과 모형별 `n`, `coverage`, `interval_score`.
- `metrics.variance[key]`: `n`, `qlike`.
- `sample`: `n`, 기준일 시작/종료, 목표일 시작/종료.
- `excluded`: 제외 기준일과 이유. 이전 계산값으로 대체하지 않는다.

## 검증과 해석 한계

`tests/test_fx_validation.py`는 직접 계산한 MAE·RMSE·구간점수·QLIKE와 산출값을 대조한다.
미래 환율·금리값을 바꾸어도 과거 점예측·구간·분산이 변하지 않는지 확인한다.
같은 기준일에 나중 지평을 추가해도 이미 계산한 앞 지평의 모의결과가 같은지,
목표일 관측 누락을 채우지 않는지, 잘못된 형식과 추정 실패가 이유를 남기는지 검증한다.
반복 정렬 검사는 빠른 결정론적 A 적합 대역을 쓰며, 별도 검사에서는 실제 A/D 추정과
시뮬레이션을 실행한다. 이는 원자료 독립 검증이 아니다.

기본 한도와 가중치는 계산 전에 고정한 구현 선택이다. 결과를 확인하고 같은 자료에서
수정해 우수성을 선언하지 않는다. 이번 평가만으로 예측 우월성·유의성·포함률 보정·
거래비용 차감 투자성과를 주장하지 않는다. 더 긴 검증에는 새로운 미사용 기간,
실시간 데이터 빈티지, 중첩 의존성을 고려한 추론이 필요하다.

실행 예:

```bash
OPENBLAS_NUM_THREADS=1 python -m pytest -q tests/test_fx_validation.py
```

기존 fx JSON에서 재계산할 때는 `pipeline`을 Python 경로에 추가하고
`build(payload["outlook"], payload["model_c"])`를 호출한다. A의 EM 재추정이 주요 CPU
병목이며 실제 자료의 기본 36회 실행은 수 분 이상 걸릴 수 있다. 경로행렬은 한 기준일씩
집계 후 해제하므로 전체 기준일 수에 비례해 모의경로 메모리가 증가하지 않는다.
