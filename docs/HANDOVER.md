## 2. 작업 방식 — 반드시 지킬 것

사용자는 이전에 같은 목적의 프로젝트를 **폐기**한 적이 있다(56커밋 규모).
폐기 사유를 사용자 본인이 이렇게 진단했다:

> "나랑 어떻게 만들지 구체적인 안이 확정도 안 됐는데 멋대로 막 만들어서 방향이 이상하게 갔다"

그래서 다음이 합의되어 있다:

1. **큰 변경은 먼저 논의하고 결정한다.** 바로 시행하지 말 것.
2. **선택이 필요하면 시안을 여러 개 만들어 보여준다.** 시안은 **반드시 실데이터**로
   계산한다(가짜 숫자 금지 — 실전에서 어떻게 읽힐지 판단해야 하므로).
3. **승인된 안만 구현한다.**
4. 구현 후 **적대적 검증**(검증 에이전트로 수식·프론트엔드 각각)을 거치고,
   확인된 결함을 고친 뒤 배포한다. 검증에서 나온 지적은 **사용자에게 정직하게 보고**한다.
5. 사용자가 "별로다"라고 하면 방어하지 말고 **무엇이 안 읽히는지** 구체적으로 파악해
   다시 만든다.

## 4. 통계·방법론 원칙 — "자의성 금지"

사용자의 제1원칙은 **외부 평가위원(교수)의 객관적·논리적 공격에 방어 가능할 것**이다.
임의 계수·임의 방식 금지. 실제로 사용자는 "단순 평균이 문제"라며 가중치 재설계를 요구했고,
검증 없이 ML을 넣자는 제안은 거부하고 **먼저 walk-forward 검증부터** 하도록 지시했다.

확립된 처리 방식:

- **모든 학습·정규화는 시점 이전 데이터만 사용** (look-ahead 차단), 재학습은 walk-forward.
- **중첩 표본에는 Newey-West HAC 표준오차**를 쓰고 그 사실을 화면에 표시.
- **다중검정 보정**: 여러 시차 중 최대값을 고르는 구조면 본페로니 보정 임계값을 쓴다
  (관계분석에서 단일시차 ±0.065 → 보정 ±0.110).
- **비정상 시계열**: 수준끼리 상관은 허구적 상관이 되므로 **변화(차분) 기준이 기본**,
  수준 선택 시 경고를 띄운다.
- **한계를 화면에 정직하게 쓴다.** 예: "어떤 요인도 1개월 뒤 하락폭은 예측하지 못했고,
  예측되는 것은 변동성이다."

### 5.1 리스크 스코어보드 (`pipeline/risk.py`)

**2층 구조** — 두 층이 전환점에서 반대로 움직이므로 하나로 합치면 둘 다 놓친다:

| 층 | 질문 | 합성 방식 |
|---|---|---|
| **현재 위험** | 지금 시장이 흔들리고 있는가 | **IC가중 + 최소바닥 8%** (매 4주 walk-forward 재학습, 엠바고 5주) |
| **잠재 위험** | 문제가 터지면 크게 다칠 상태인가 | 활성 요인 **동일가중** |

- **왜 IC가중인가**: walk-forward 표본 외 검증(2010~2026, 864주, 위기주 136주)에서
  동일가중 IC 0.512 → IC가중 0.587, 위기 판별 AUC 0.602 → 0.608. 하네스는
  `pipeline/research/wf_validation.py` (CI 미실행, 수동 재검증용).
- **왜 최소바닥 8%인가**: 학습이 커브·CDS 가중을 0으로 보내는데, 감시 도구가 그 채널에
  눈을 감으면 2011년형(국가신용발) 위기를 놓친다. 커버리지 보험이며 비용은 IC −0.015뿐.
- **왜 잠재 위험은 동일가중인가**: 목적이 단기 예측이 아니라 축적 감시라 IC 학습 타깃이
  다르다. **모델 랩에서 장기 지평 타깃으로 별도 검증 예정.**
- **백분위 창 = 전체 이력(2001~)**. 10년 창은 2026년 기준 **2008년이 빠져서** 부적절하다
  (커브 요인에서 21p 차이 발생).
- 등급 = 점수 4등분(낮음/보통/주의/경계). 단순하지만 자의성 없음. 더 정교한 기준
  (과거 위기 국면 매칭)은 모델 랩 백로그.
- **검증에서 잡은 실전 버그**: 소스별 최종 관측일 차이(bb 07-20 vs info 07-27)로 마지막 주에
  일부 지표만 남아 요인 점수가 왜곡됐다 → "시작된 지표가 전부 있는 주만 사용"으로 수정.

### 5.3 환헤지 (`pipeline/hedge.py`)

**경제/회계 이중 관점**이 핵심. 사용자가 알려준 회계 처리를 그대로 모형화했다:

```
장부가 해외채권 + FX스왑의 회계 손익 (채권 시가평가액 변동은 미반영 — 유효이자율법)
 ① 유효이자        상수
 ② 환산손익        N × Δ환율
 ③ 스왑 환파트     −N × h × Δ환율   (②와 동액·반대부호 상쇄)
 ④ 스왑레이트 캐리  N × h × s₀       (계약 시 확정)
 ⑤ 스왑 MTM       N × h × τ × (−Δ시장스왑레이트)   τ = 만기/2
```

- **함의**: 회계 관점에는 자연 쿠션이 없어 **손익변동 최소는 언제나 헤지 100%**,
  판단 변수는 비용뿐. 경제 관점은 반대로 주식은 낮은 헤지가 변동성 최소(환쿠션).
- **스왑 만기 기본값 9개월** — 사용자 실무의 금액가중평균.
- 7통화: USD·EUR·JPY·CNY·AUD·CAD·GBP. **위안은 데이터 없어 비활성**.
- **검증에서 잡은 중대 오류**: MTM 최악월 부호를 반대로 집계했었다(손실은 스왑레이트
  **상승** 시 발생). 실제 최악은 2008-12 **+4.92%p**이고 앞서 발표한 값의 1.8배였다.
- 금리차 '변화' 프록시는 실측과 상관 0.07로 **검증 실패 → 폐기**, 전 통화에 달러 실측 적용.

### 5.4 관계분석 (`pipeline/panel.py` + `app.js` 통계 엔진)

주간 1116주 패널(리스크 11계열 + 시장변수 30종). 통계는 **브라우저에서** 실행:
`pearson`/`spearman`/`crossCorr`/`ols`(+Newey-West HAC)/`normInv`.
단위검증 완료(완전적합 계수 복원, 교차상관 시차 부호, A·A⁻¹=I, p(1.96)=0.05, HAC SE 증가).

**실데이터가 말하는 것(중요)**: 현재 위험 지표는 **동행 지표이지 선행 지표가 아니다**.
KOSPI(−0.65)·달러/원(+0.45)·미국채 10년(−0.20) 모두 시차 0에서 최대 상관.
달러/원 4주 예측 회귀는 R² 2.3%. 화면이 스스로 이 한계를 보여준다.

### 6.1 ETF 카테고리 시리즈의 표시통화 — 판정 완료 (물어보지 말 것)

두 번 물어도 답이 없던 항목이라 **데이터로 직접 판정했다.** 결론:
`ETF` 카테고리의 `미국*`·`달러유동성`은 전부 **원화 환산(완전 환노출)**,
`한국*`·`원화유동성`은 원화 자산, 그리고 **`미국종합`·`한국종합`만 ETF가 아니라 지수**다
(`미국종합` = 달러표시, `한국종합` = 원화표시).

판정 방법 — 단순 상관으로는 갈리지 않아 3단계로 좁혔다:

1. **일별 단순회귀는 결론을 내지 못한다.** 달러원에 대한 베타가 0.53~0.76의 어중간한
   값으로 나온다. 원인이 둘 섞여 있어서다 — (a) 한국 상장 ETF 종가와 환율 고시시각의
   **비동시성**, (b) 위험회피 국면에 미국채는 오르고 크레딧은 내리는데 원화는 약세라
   완전 환노출이어도 β = 1 + cov(현지수익률, 환율)/var(환율) ≠ 1.
2. **월간으로 가면 (a)가 사라진다.** 대조군 `달러유동성`(정의상 달러 MMF이므로 현지
   변동성 ≈ 0, 따라서 참값 β = 1.0)이 **β 0.981**로 나오는 것이 추정기의 바닥 눈금이다.
   같은 자에 대고 재면 `미국단기` 0.965 · `미국중기` 0.936 · `미국장기` 0.915 ·
   `미국초장기` 0.871. 반면 `한국*`·`미국종합`은 전부 |β| < 0.12.
3. **크레딧만 남은 (b)는 직교 식별로 갈랐다.** `미국투자등급`(0.641)·`미국하이일드`(0.583)만
   유독 낮은 것이 부분헤지인지 공분산인지는 단순회귀로 못 가린다(잔차를 환율로 만든
   것이라 순환논리). 그래서 현지수익률 대리변수를 **환율과 무관한 원천**(블룸버그 달러표시
   일드)에서 가져와 `r_ETF = a + b·r_FX + c·(−Δ일드)` 로 재추정했다. 월간 결과:

   | 시리즈 | 일드 대리변수 | b(환율) | 95% CI |
   |---|---|---|---|
   | 달러유동성 *(대조군, 참값 1.0)* | 미국_3m | **0.980** | [0.96, 1.01] |
   | 미국단기 | 미국_2y | 0.978 | [0.96, 1.00] |
   | 미국중기 | 미국_7y | 0.970 | [0.95, 0.99] |
   | 미국장기 | 미국_10y | 0.969 | [0.95, 0.99] |
   | 미국하이일드 | 미국_하이일드_일드 | 0.945 | [0.89, 1.00] |
   | 미국초장기 | 미국_30y | 0.916 | [0.88, 0.95] |
   | 미국투자등급 | 미국_투자등급_일드 | 0.897 | [0.85, 0.95] |
   | 한국종합 *(대조군)* | 한국_5y | −0.009 | [−0.02, 0.01] |
   | 미국종합 *(대조군)* | 미국_10y | −0.083 | [−0.10, −0.06] |

   현지수익률을 통제하자 크레딧 두 개가 0.90~0.95로 올라왔다 → **부분헤지가 아니라
   공분산이었다.** 가설을 직접 확인: corr(Δ투자등급 스프레드, Δ달러원) = +0.39,
   corr(Δ하이일드 스프레드, Δ달러원) = +0.43 — 스프레드 확대와 원화 약세가 실제로 동행한다.

**이 결론이 코드에 갖는 의미:**

- `hedge.py` 가 달러 채권 프록시로 쓰는 `bb:미국종합` 은 **달러표시가 맞다**(β ≈ 0).
  환율을 따로 모형화하는 헤지 엔진에 넣기에 올바른 선택이며, 고칠 것 없다.
- 반대로 **`ETF` 카테고리의 `미국*` 6종을 자산배분 최적화기에 그대로 넣으면 환율이
  이중계상된다.** 헤지비율 슬라이더가 FX를 따로 다루는데 프록시 자체에 FX가 이미
  들어있기 때문이다. 쓰려면 반드시 `현지수익률 = ETF 수익률 − Δlog(달러원)` 으로
  FX를 벗겨낸 뒤 헤지비율을 적용할 것.
- 재현: 판정 스크립트는 비공개 데이터를 읽으므로 저장소에 커밋하지 않았다. 위 3단계
  회귀는 `bb:달러원` 과 각 시리즈의 월간 로그수익률만 있으면 20줄로 재작성된다.

**확신의 정도를 구분해 둘 것.** 회귀가 **단정하는 것은 환노출 유무뿐**이다.
`미국종합`이 "달러표시 지수"라는 라벨은 회귀가 아니라 **수준값의 눈금**에서 온
보조 근거다 — 값이 1,017 → 2,353(24.6년, 연 +3.4%)으로 지수의 눈금이지 한국 상장
ETF의 눈금(1만·5만·10만 원에서 출발)이 아니다. 대안 해석인 "환헤지형 ETF"도 β ≈ 0을
내지만, 그 경우 한국이 미국보다 금리가 높던 구간의 헤지 프리미엄이 얹혀 달러
종합채권보다 눈에 띄게 높은 수익률이 나와야 한다. 다만 **자산배분·환헤지 어느 쪽에도
이 구분은 영향이 없다** — 필요한 성질은 "FX 노출이 없다"이고 그건 확정됐다.

### 7.2 설계 시 반드시 반영할 것

1. **장부가 자산을 그냥 평균-분산 최적화기에 넣으면 안 된다.** 가격 변동성이 0이라
   최적화기가 무한정 사려 한다. 장부가의 위험은 **재투자 위험 + ALM(듀레이션 갭)**으로
   정의하고, **회계 관점 / 경제 관점 토글**을 제공해야 한다.
2. **환헤지와 분리할 수 없다.** 장부가 해외채권의 손익 변동성은 사실상 환율이 지배하므로,
   헤지비율 슬라이더가 자산배분 화면의 숫자를 직접 바꾼다. 같은 계산 엔진의 두 단면으로 설계.
3. **최적화는 브라우저에서** 돌아야 한다(슬라이더 인터랙션). 다만 원본 수익률을 공개하면
   라이선스 문제가 생기므로 → **빌드 시점에 공분산 행렬 + 기대수익 벡터만 게시**하고
   브라우저는 작은 최적화기만 돌린다. (환헤지에서 이미 이 패턴을 씀 — `hedge.json` `sim`)
4. **데이터 재료 — 재확인 결과 이전 기록("ETF 17종, 2001~2026 25년치")은 낙관적이었다.**
   ETF 계열의 시작일이 제각각이라 **공통 구간을 잡으면 25년이 아니라 8년으로 줄어든다**
   (`한국중기크레딧` 2025-05, `한국장기국채` 2023-11, `미국하이일드` 2017-10).
   25년 공분산을 원하면 ETF가 아니라 **지수·금리 계열**로 가야 한다:

   | 자산군 | 25년 가능한 프록시 | 시작 | ETF 대안(짧음) |
   |---|---|---|---|
   | 국내주식 | `bb:한국_KOSPI_TR` | 2001-12 | — |
   | 해외주식 | `idx:ACWI` 2006-12 / `bb:미국_S&P500_TR` | 2001-12 | — |
   | 해외채권(달러표시) | `bb:미국종합` | 2001-12 | `미국*` ETF는 FX 포함(§6.1) |
   | 국내채권 | `bb:한국_5y`+`synth_bond_tr` | 2001-12 | `bb:한국종합` 2009-07 |
   | 국내크레딧 | `bb:한국_크레딧_일반회사채_AA0_3y` | 2006-01 | `한국*크레딧` 2021~2025 |
   | 단기자금 | `info:한국_3m` | 2001-01 | `원화유동성` 2022-04 |
   | 환율 | `bb:달러원` | 2001-12 | — |

   `synth_bond_tr()` 는 이미 `hedge.py` 에 있고 달러 실지수 대비 상관 0.85로 검증돼 있다
   (§5.3). 즉 **자산배분도 같은 함수를 재사용**하면 25년 공통 구간이 확보된다.
   ETF 계열은 이 합성 프록시의 **교차검증용**으로 쓰는 것이 맞는 위치다.

| ① | 동일 샤프 앵커 | **유지 확정.** 단 ⑤와 함께 산식이 자국통화 기준으로 바뀜(아래). 선행 PER 확보 시 관측값(어닝일드−무위험)으로 교체 예정 |

| ④ | 표본 재추출 드릴다운 격하 | **확정** (그대로) |

| ⑦ | 구현 착수 | **확정** (사후 승인 완료) |

## 8. 그 다음 — 모델 랩 (기능 4)

- 모델을 **표준 인터페이스**로 정의: "입력 = t시점까지의 데이터 → 출력 = 특정 변수의 k개월 후 전망".
  어떤 논문 모델이든 이 틀에 넣으면 동일 기준(적중률·오차·정보계수)으로 리더보드에 오른다.
- 초기에는 기본 모델 몇 개(금리: 포워드 내재·테일러류 / 주식: 포워드 어닝일드−무위험금리 /
  FX: 금리평형·캐리)를 내장해 틀을 검증. 논문 모델은 사용자가 업로드할 때마다 추가.
- **1호 입주 검증 대상**(이미 예약됨):
  ① 잠재 위험 층의 가중 학습(장기 지평 타깃)
  ② CISS형 상관 집계(간이 구현은 열세였으므로 정식 일별 구현으로 재도전)
  ③ 리스크 등급 밴드를 과거 위기 국면 매칭으로 재설정
- 챔피언 모델의 전망치가 환헤지·자산배분의 기본 가정으로 주입되고, 화면에는 항상
  **"이 기대수익은 모델 X, 최근 5년 적중률 N%"** 출처가 붙는다.

## 9. 알아두면 시간 아끼는 것들

- **테스트가 있다** (다른 세션이 추가, 81개 통과 / 약 50초). `python -m pytest` —
  합성 픽스처(`tests/synth.py`)로 돌아서 **비공개 데이터 없이 실행된다.**
  코드를 고치면 이걸 먼저 돌릴 것. CI도 `test → build(+게이트) → deploy` 순서다.
- **배포 게이트가 있다** (`pipeline/check_output.py`). `process.py` 는 risk/hedge 실패를
  try/except 로 삼키고 exit 0 으로 끝나므로, 이 게이트가 없으면 섹션이 빠진 대시보드가
  초록불로 배포된다. JSON 15개 계약은 세 곳(`process.payloads`·`app.js FILES`·
  `check_output.EXPECTED`)에 적혀 있고 `tests/test_contract.py` 가 불일치를 잡는다.
- **요인 정의는 `risk.derive_inputs()` + `risk.factor_specs()`** 로 모듈 수준에 나와 있다.
  `research/wf_validation.py` 가 **같은 정의를 import** 하므로, 요인을 고치면 배포 코드와
  검증 하네스가 함께 바뀐다(예전처럼 양쪽에 따로 적어 두면 조용히 갈라진다).
- **결측·이상치 검증이 약하다.** 신선도는 시리즈 *끝*만 본다. 단일일 스파이크 필터는
  `hedge.py` `despike()`에만 있다(유로 2005-04-29 ×100 오류, 위안 2008-05-30 오류를 실제로 잡음).
  → 파이프라인 공통 규칙으로 올리는 것이 백로그.
- **`AIs` 저장소**(검증 패널 에이전트 정의)는 이 코드와 런타임 의존이 없다.
- **다른 세션이 같은 브랜치에 PR을 머지한다** (실제로 여러 번 발생: `CLAUDE.md`·의존성 고정,
  공용 산식 통합 + 테스트 + 배포 게이트). **푸시 전 반드시 `git fetch` → 리베이스**하고,
  리팩터링으로 함수 위치가 바뀌었을 수 있으니 작업 시작 전에 최신 코드를 확인할 것.
- 사용자는 GitHub 설정을 **웹 UI에서만** 한다. 토큰·시크릿·Pages 안내는 `docs/SETUP.md`.
- 제 샌드박스에서는 `github.io` 접속이 차단된다. 배포 확인은 Actions API로 하고,
  최종 화면 확인은 사용자에게 부탁한다.
