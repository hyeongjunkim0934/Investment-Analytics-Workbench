## 2. 작업 방식 — 반드시 지킬 것

사용자는 이전에 같은 목적의 프로젝트를 **폐기**한 적이 있다(56커밋 규모).
폐기 사유를 사용자 본인이 이렇게 진단했다:

> "나랑 어떻게 만들지 구체적인 안이 확정도 안 됐는데 멋대로 막 만들어서 방향이 이상하게 갔다"

그래서 다음이 합의되어 있다:

1. **큰 변경은 먼저 논의하고 결정한다.** 바로 시행하지 말 것.
2. **선택이 필요하면 시안을 여러 개 만들어 보여준다.** 시안은 **반드시 실데이터**로
   계산한다(가짜 숫자 금지 — 실전에서 어떻게 읽힐지 판단해야 하므로).
3. **승인된 안만 구현한다.**
4. 구현 후 **적대적 검증**(검증 에이전트로 수식·프론트엔드 각각)을 거치고,
   확인된 결함을 고친 뒤 배포한다. 검증에서 나온 지적은 **사용자에게 정직하게 보고**한다.
5. 사용자가 "별로다"라고 하면 방어하지 말고 **무엇이 안 읽히는지** 구체적으로 파악해
   다시 만든다.

## 3. 디자인 원칙 — 사용자 피드백으로 확립된 것

### 3.1 절대 규칙

- **2단계 구조**: 기본 화면 = **결론만** 직관적으로 / 궁금하면 **클릭해서 상세**로.
  모든 화면에 적용한다(리스크 요인 행 → 상세 오버레이, 환헤지 → 시뮬레이터).
- **금융인이 평생 봐온 형태만 쓴다** — 선 그래프 + 숫자 + 표.
  인코딩을 새로 배워야 하는 시각화는 거부당했다.
- **모든 숫자는 그 자리에서 한 줄로 설명한다.** 점수·등급 정의를 화면에 상시 노출
  (예: 리스크 화면의 "점수 읽는 법" 상자).
- **화면이 답하는 질문을 맨 위에 한 줄로 쓴다** (`이 화면이 답하는 질문 — …`).
- 톤은 **"권고"가 아니라 "모델 참고치"**.

> `ended` 를 못 쏘므로 `done()` 이 영영 실행되지 않는다 → `data-transition` 표식이 DOM 에
> 남고 → 돌아왔을 때 `mountVillageVideo` 의 첫 가드가 재마운트를 거부한다. 결과는 전환
> 중간 프레임에서 얼어붙고 SVG 모션까지 꺼진 **완전 정지 화면이며 스스로 회복하지 못한다**
> (브라우저 실측: currentTime 2.5s 고정, 4초 뒤에도 동일). 사용자가 처음 문제 삼은 "정지
> 화면" 바로 그것이라 특히 위험하다. 그래서 pause 대상은 **`video[data-idle]` 로 한정**하고,
> 이 한정을 강제하는 회귀 테스트를 넣었다
> (`test_leaving_village_does_not_pause_the_theme_transition`).
>
> **주의 — 이 컨테이너의 Playwright Chromium 은 H.264 를 디코드하지 못한다**
> (`canPlayType('video/mp4; codecs="avc1.42E01E"')` → `""`, `village-dusk.mp4` 는
> `DEMUXER_ERROR_NO_SUPPORTED_STREAMS`). 즉 **전환 연출(mp4)과 루프의 mp4 폴백은 여기서
> 재생 검증이 불가능하다** — 이 환경에서 전환 영상은 즉시 error→done 으로 떨어지므로 위
> 교착도 그냥 브라우저를 열어서는 재현되지 않는다(전환 URL 에 VP9 바이트를 물려
> 재현했다). mp4 4개는 ffmpeg 디코드·프레임 실측으로만 검증됐고, **실제 H.264 브라우저에서의
> 눈으로 보는 확인은 남아 있다.**

> **2026-08-04 — 테마 축이 둘로 갈라졌다. 「자동 낮밤순환 금지」 규약은 사용자가 해제했다.**

> 개별로 들어가서 보는 대시보드 배경은 검은색을 디폴트로 해줘. … 메인화면은(village) 그냥
> 놔두면 15초 간격으로 낮에서 밤으로, 밤에서 다시 낮으로 바뀌게끔 … 수기로 밤과 낮을 바꾸는
> 기능은 그대로 두되, 그 기능으로 바꾸어도 그대로 냅두면 마찬가지로 15초 지나면 다시 밤낮이

## 4. 통계·방법론 원칙 — "자의성 금지"

사용자의 제1원칙은 **외부 평가위원(교수)의 객관적·논리적 공격에 방어 가능할 것**이다.
임의 계수·임의 방식 금지. 실제로 사용자는 "단순 평균이 문제"라며 가중치 재설계를 요구했고,
검증 없이 ML을 넣자는 제안은 거부하고 **먼저 walk-forward 검증부터** 하도록 지시했다.

확립된 처리 방식:

- **모든 학습·정규화는 시점 이전 데이터만 사용** (look-ahead 차단), 재학습은 walk-forward.
- **중첩 표본에는 Newey-West HAC 표준오차**를 쓰고 그 사실을 화면에 표시.
- **다중검정 보정**: 여러 시차 중 최대값을 고르는 구조면 본페로니 보정 임계값을 쓴다
  (관계분석에서 단일시차 ±0.065 → 보정 ±0.110).
- **비정상 시계열**: 수준끼리 상관은 허구적 상관이 되므로 **변화(차분) 기준이 기본**,
  수준 선택 시 경고를 띄운다.
- **한계를 화면에 정직하게 쓴다.** 예: "어떤 요인도 1개월 뒤 하락폭은 예측하지 못했고,
  예측되는 것은 변동성이다."

### 5.1 리스크 스코어보드 (`pipeline/risk.py`)

**2층 구조** — 두 층이 전환점에서 반대로 움직이므로 하나로 합치면 둘 다 놓친다:

| 층 | 질문 | 합성 방식 |
|---|---|---|
| **현재 위험** | 지금 시장이 흔들리고 있는가 | **IC가중 + 최소바닥 8%** (매 4주 walk-forward 재학습, 엠바고 5주) |
| **잠재 위험** | 문제가 터지면 크게 다칠 상태인가 | 활성 요인 **동일가중** |

- **왜 IC가중인가**: walk-forward 표본 외 검증(2010~2026, 864주, 위기주 136주)에서
  동일가중 IC 0.512 → IC가중 0.587, 위기 판별 AUC 0.602 → 0.608. 하네스는
  `pipeline/research/wf_validation.py` (CI 미실행, 수동 재검증용).
- **왜 최소바닥 8%인가**: 학습이 커브·CDS 가중을 0으로 보내는데, 감시 도구가 그 채널에
  눈을 감으면 2011년형(국가신용발) 위기를 놓친다. 커버리지 보험이며 비용은 IC −0.015뿐.
- **왜 잠재 위험은 동일가중인가**: 목적이 단기 예측이 아니라 축적 감시라 IC 학습 타깃이
  다르다. **모델 랩에서 장기 지평 타깃으로 별도 검증 예정.**
- **백분위 창 = 전체 이력(2001~)**. 10년 창은 2026년 기준 **2008년이 빠져서** 부적절하다

#### 5.2.1 이벤트 브리핑 카드 + 음성 (2026-08-11 사용자 승인 — "AI 앵커" 요청의 1·2단계)

### 5.3 환헤지 (`pipeline/hedge.py`)

**경제/회계 이중 관점**이 핵심. 사용자가 알려준 회계 처리를 그대로 모형화했다:

```
장부가 해외채권 + FX스왑의 회계 손익 (채권 시가평가액 변동은 미반영 — 유효이자율법)
 ① 유효이자        상수
 ② 환산손익        N × Δ환율
 ③ 스왑 환파트     −N × h × Δ환율   (②와 동액·반대부호 상쇄)
 ④ 스왑레이트 캐리  N × h × s₀       (계약 시 확정)
 ⑤ 스왑 MTM       N × h × τ × (−Δ시장스왑레이트)   τ = 만기/2
```

- **함의**: 회계 관점에는 자연 쿠션이 없어 **손익변동 최소는 언제나 헤지 100%**,
  판단 변수는 비용뿐. 경제 관점은 반대로 주식은 낮은 헤지가 변동성 최소(환쿠션).
- **스왑 만기 기본값 9개월** — 사용자 실무의 금액가중평균.
- 7통화: USD·EUR·JPY·CNY·AUD·CAD·GBP. **위안은 데이터 없어 비활성**.
- **검증에서 잡은 중대 오류**: MTM 최악월 부호를 반대로 집계했었다(손실은 스왑레이트
  **상승** 시 발생). 실제 최악은 2008-12 **+4.92%p**이고 앞서 발표한 값의 1.8배였다.
- 금리차 '변화' 프록시는 실측과 상관 0.07로 **검증 실패 → 폐기**, 전 통화에 달러 실측 적용.

### 6.1 ETF 카테고리 시리즈의 표시통화 — 판정 완료 (물어보지 말 것)

두 번 물어도 답이 없던 항목이라 **데이터로 직접 판정했다.** 결론:
`ETF` 카테고리의 `미국*`·`달러유동성`은 전부 **원화 환산(완전 환노출)**,
`한국*`·`원화유동성`은 원화 자산, 그리고 **`미국종합`·`한국종합`만 ETF가 아니라 지수**다
(`미국종합` = 달러표시, `한국종합` = 원화표시).

판정 방법 — 단순 상관으로는 갈리지 않아 3단계로 좁혔다:

1. **일별 단순회귀는 결론을 내지 못한다.** 달러원에 대한 베타가 0.53~0.76의 어중간한
   값으로 나온다. 원인이 둘 섞여 있어서다 — (a) 한국 상장 ETF 종가와 환율 고시시각의
   **비동시성**, (b) 위험회피 국면에 미국채는 오르고 크레딧은 내리는데 원화는 약세라
   완전 환노출이어도 β = 1 + cov(현지수익률, 환율)/var(환율) ≠ 1.
2. **월간으로 가면 (a)가 사라진다.** 대조군 `달러유동성`(정의상 달러 MMF이므로 현지
   변동성 ≈ 0, 따라서 참값 β = 1.0)이 **β 0.981**로 나오는 것이 추정기의 바닥 눈금이다.
   같은 자에 대고 재면 `미국단기` 0.965 · `미국중기` 0.936 · `미국장기` 0.915 ·
   `미국초장기` 0.871. 반면 `한국*`·`미국종합`은 전부 |β| < 0.12.
3. **크레딧만 남은 (b)는 직교 식별로 갈랐다.** `미국투자등급`(0.641)·`미국하이일드`(0.583)만
   유독 낮은 것이 부분헤지인지 공분산인지는 단순회귀로 못 가린다(잔차를 환율로 만든
   것이라 순환논리). 그래서 현지수익률 대리변수를 **환율과 무관한 원천**(블룸버그 달러표시
   일드)에서 가져와 `r_ETF = a + b·r_FX + c·(−Δ일드)` 로 재추정했다. 월간 결과:

   | 시리즈 | 일드 대리변수 | b(환율) | 95% CI |
   |---|---|---|---|
   | 달러유동성 *(대조군, 참값 1.0)* | 미국_3m | **0.980** | [0.96, 1.01] |
   | 미국단기 | 미국_2y | 0.978 | [0.96, 1.00] |
   | 미국중기 | 미국_7y | 0.970 | [0.95, 0.99] |
   | 미국장기 | 미국_10y | 0.969 | [0.95, 0.99] |
   | 미국하이일드 | 미국_하이일드_일드 | 0.945 | [0.89, 1.00] |
   | 미국초장기 | 미국_30y | 0.916 | [0.88, 0.95] |
   | 미국투자등급 | 미국_투자등급_일드 | 0.897 | [0.85, 0.95] |
   | 한국종합 *(대조군)* | 한국_5y | −0.009 | [−0.02, 0.01] |
   | 미국종합 *(대조군)* | 미국_10y | −0.083 | [−0.10, −0.06] |

   현지수익률을 통제하자 크레딧 두 개가 0.90~0.95로 올라왔다 → **부분헤지가 아니라
   공분산이었다.** 가설을 직접 확인: corr(Δ투자등급 스프레드, Δ달러원) = +0.39,
   corr(Δ하이일드 스프레드, Δ달러원) = +0.43 — 스프레드 확대와 원화 약세가 실제로 동행한다.

**이 결론이 코드에 갖는 의미:**

- `hedge.py` 가 달러 채권 프록시로 쓰는 `bb:미국종합` 은 **달러표시가 맞다**(β ≈ 0).
  환율을 따로 모형화하는 헤지 엔진에 넣기에 올바른 선택이며, 고칠 것 없다.
- 반대로 **`ETF` 카테고리의 `미국*` 6종을 자산배분 최적화기에 그대로 넣으면 환율이
  이중계상된다.** 헤지비율 슬라이더가 FX를 따로 다루는데 프록시 자체에 FX가 이미
  들어있기 때문이다. 쓰려면 반드시 `현지수익률 = ETF 수익률 − Δlog(달러원)` 으로
  FX를 벗겨낸 뒤 헤지비율을 적용할 것.
- 재현: 판정 스크립트는 비공개 데이터를 읽으므로 저장소에 커밋하지 않았다. 위 3단계
  회귀는 `bb:달러원` 과 각 시리즈의 월간 로그수익률만 있으면 20줄로 재작성된다.

**확신의 정도를 구분해 둘 것.** 회귀가 **단정하는 것은 환노출 유무뿐**이다.
`미국종합`이 "달러표시 지수"라는 라벨은 회귀가 아니라 **수준값의 눈금**에서 온
보조 근거다 — 값이 1,017 → 2,353(24.6년, 연 +3.4%)으로 지수의 눈금이지 한국 상장
ETF의 눈금(1만·5만·10만 원에서 출발)이 아니다. 대안 해석인 "환헤지형 ETF"도 β ≈ 0을
내지만, 그 경우 한국이 미국보다 금리가 높던 구간의 헤지 프리미엄이 얹혀 달러
종합채권보다 눈에 띄게 높은 수익률이 나와야 한다. 다만 **자산배분·환헤지 어느 쪽에도
이 구분은 영향이 없다** — 필요한 성질은 "FX 노출이 없다"이고 그건 확정됐다.

| 대출금 | 보험계약자 약관대출 | 금액·수익률 변동 작음 → **준고정**, 최적화 대상에서 제외 |
| 단기자금 | MMF·MMDA | 자산배분에 포함 |

### 7.2 설계 시 반드시 반영할 것

1. **장부가 자산을 그냥 평균-분산 최적화기에 넣으면 안 된다.** 가격 변동성이 0이라
   최적화기가 무한정 사려 한다. 장부가의 위험은 **재투자 위험 + ALM(듀레이션 갭)**으로
   정의하고, **회계 관점 / 경제 관점 토글**을 제공해야 한다.
2. **환헤지와 분리할 수 없다.** 장부가 해외채권의 손익 변동성은 사실상 환율이 지배하므로,
   헤지비율 슬라이더가 자산배분 화면의 숫자를 직접 바꾼다. 같은 계산 엔진의 두 단면으로 설계.
3. **최적화는 브라우저에서** 돌아야 한다(슬라이더 인터랙션). 다만 원본 수익률을 공개하면
   라이선스 문제가 생기므로 → **빌드 시점에 공분산 행렬 + 기대수익 벡터만 게시**하고
   브라우저는 작은 최적화기만 돌린다. (환헤지에서 이미 이 패턴을 씀 — `hedge.json` `sim`)
4. **데이터 재료 — 재확인 결과 이전 기록("ETF 17종, 2001~2026 25년치")은 낙관적이었다.**
   ETF 계열의 시작일이 제각각이라 **공통 구간을 잡으면 25년이 아니라 8년으로 줄어든다**
   (`한국중기크레딧` 2025-05, `한국장기국채` 2023-11, `미국하이일드` 2017-10).
   25년 공분산을 원하면 ETF가 아니라 **지수·금리 계열**로 가야 한다:

   | 자산군 | 25년 가능한 프록시 | 시작 | ETF 대안(짧음) |
   |---|---|---|---|
   | 국내주식 | `bb:한국_KOSPI_TR` | 2001-12 | — |
   | 해외주식 | `idx:ACWI` 2006-12 / `bb:미국_S&P500_TR` | 2001-12 | — |
   | 해외채권(달러표시) | `bb:미국종합` | 2001-12 | `미국*` ETF는 FX 포함(§6.1) |
   | 국내채권 | `bb:한국_5y`+`synth_bond_tr` | 2001-12 | `bb:한국종합` 2009-07 |
   | 국내크레딧 | `bb:한국_크레딧_일반회사채_AA0_3y` | 2006-01 | `한국*크레딧` 2021~2025 |
   | 단기자금 | `info:한국_3m` | 2001-01 | `원화유동성` 2022-04 |
   | 환율 | `bb:달러원` | 2001-12 | — |

   `synth_bond_tr()` 는 이미 `hedge.py` 에 있고 달러 실지수 대비 상관 0.85로 검증돼 있다
   (§5.3). 즉 **자산배분도 같은 함수를 재사용**하면 25년 공통 구간이 확보된다.
   ETF 계열은 이 합성 프록시의 **교차검증용**으로 쓰는 것이 맞는 위치다.

> 보간)은 한 줄도 안 바뀌었다. **커브를 읽는 법**이 「최신 호가」에서 **「최근

>
> - **이것은 스파이크가 아니라 톱니(측정 잡음)다.** 일간 변화 Δ 의 1차 자기상관이
>   **12계열 전부 음수**(−0.15 ~ −0.63. 순수 1일 측정잡음 MA(1) 의 이론 하한이 −0.5).
>   즉 호가는 튀었다 되돌아온다. 기존 `hedge.despike()` 는 재사용할 수 없다 —
>   `pct_change` 기반인데 EUR HP 12M 은 부호를 넘나든다.
> - **최신 호가는 한 번의 빌드로 게시값을 최대 5.50%p 움직인다**(EUR 3M. USD 3M
>   1.75%p). N=5 에서 0.16 / 0.53%p.
> - **N=5 가 자의적이지 않은 이유(두 독립 유도)**: ① AR(2)≈0 이라 잡음 기억이 1일이고
>   그 2배 이상을 덮는 최소 홀수창이 5 ② 지연 (N−1)/2 = 2영업일로 "최신 호가"라는
>   화면 성격을 유지한다. N=20 은 더 안정적이지만 9.5영업일 지연이라 성격이 바뀐다.
> - **선행 조건이었던 이중 경로를 먼저 합쳤다.** `hedge.py` 와 `alloc.py` 가 같은 HP
>   시리즈를 각자 `iloc[-1]` 로 읽고 있었고, 두 산식이 우연히 같아 −0.9750 으로
>   일치했을 뿐이다. 한쪽만 고치면 같은 화면의 두 숫자가 갈라진다 →
>   `common.hp_curve()` 하나로 통합했고, 통합 자체를 테스트가 강제한다.
> - **부수 해소**: HP↔SMB 괴리 문구. 겹치는 421일에서 corr 0.9644 · 평균차 +0.038%p ·
>   sd 0.127 · 범위 −1.35~+0.70 인데, 최신 호가 기준 오늘의 괴리 −0.70%p 는 관측
>   최저 근처의 꼬리였다. N=5 로 **−0.15%p** 가 되어 역사적 평균차와 맞는다.
>
> **과대선전 금지 — 중앙값은 커브의 비단조성을 고치지 못한다.** 3/6/12개월이 한
> 방향으로 정렬되지 않는 날의 비율은 달러 34.2%→**34.8%**, 유로 26.4%→**28.8%**,
> 엔 10.0%→**10.6%**, 호주 23.0%→**23.0%** 로 **오히려 늘거나 그대로**다(설계 당시
> `[uncertain]` 로 남아 있던 N=5 값을 이번에 실측했다). 비단조성은 잡음이 아니라
> 커브의 실제 성질이므로 `limits` 에 이 수치를 그대로 적었다.
>
> **되돌리기는 `HP_MEDIAN_N = 1` 한 글자다** — 창 1의 중앙값은 최신 호가와 같다.
> 화면 문구도 파이프라인의 `hedge.json.cost_read.label` 을 그대로 쓰므로 함께 되돌아간다
> (「25년 평균」 하드코딩으로 같은 사고를 한 번 겪었기에 문자열을 화면에 두지 않았다).

### 이 파일이 채우는 빈자리 — 「넓은 상승인가 좁은 상승인가」

기존 456개 시리즈는 **전부 가격·금리·스프레드**다. "지수가 올랐다"는 말할 수 있어도
그 상승이 전 종목이 함께 오른 것인지 대형주 몇 개가 끈 것인지는 **답할 수 있는
시리즈가 하나도 없었다.** 시장 폭이 그 구분을 준다.

실데이터 첫 관측(2026-08-03)이 바로 그 사례다: 상승 종목이 하락의 **2.86배**인데
**52주 신고가권 239 vs 신저가권 605**(순 −366, 상장 종목의 −7.96%). 즉 오른 종목이
훨씬 많은 날에 52주 바닥을 깨는 종목이 더 많았다. 화면이 이것을
「겉은 상승, 속은 갈라짐」으로 판정한다.

§5.4 가 기록한 대로 **현재 위험 지표는 동행 지표이지 선행 지표가 아니다**(KOSPI −0.65 등
전부 시차 0에서 최대 상관). 시장 폭은 몇 안 되는 선행 후보다.

### 하지 않은 것 — 위험 모형에 넣지 않았다

`risk.py` 의 요인 점수는 백분위·z 점수와 워크포워드 재적합(`FLOOR`·`EMBARGO_W`·
`REFIT_EVERY_W`)을 쓴다. **관측 1일로는 계산 자체가 불가능**하고, 이력이 쌓이기 전에
넣으면 그것이 곧 자의성이다. 지금은 **게시만** 한다. 화면도 관측이 2일 미만이면
차트를 그리지 않고 "아직 하루치입니다"라고 적는다 — 점 하나짜리 차트는 정보가 0인데
"이력이 있다"로 읽힌다.

### 공개 범위 — 안 읽는 것이 읽는 것만큼 중요하다

리포트에는 티커·회사명·현재가·시가총액·52주 고저가 **약 7,000종목** 규모로 들어 있고
(`S&P500 Daily` 등 상세 시트 5개), 이 저장소의 산출물은 공개 페이지로 나간다.
`pipeline/breadth.py` 는 **`Market Overview` 시트의 집계 블록만** 읽는다 — 상세 시트는
열지도 않는다. `tests/test_breadth.py` 가 상세 시트를 **일부러 만들어 넣고** 결과에

## 7.6 환헤지·자산배분 구조 재검토 (2026-08-05) — **「최적 헤지비율 한 점」 폐기**

### 무엇이 틀렸나 (실측)

- `corr(해외주식, 달러/원)` = **−0.632**(전체) / −0.594(2010+) / −0.520(2015+) / −0.483(spx02).
  **자연헤지 통념은 데이터로 확인되고 최근 구간에서도 부호가 유지된다.**
- 해외주식만 담은 포트폴리오의 위험최소 헤지비율은 **9.8%** — 거의 오픈이 맞다.
  100% 헤지하면 σ 12.46% → 16.13%(**+3.67%p**). 모형은 처음부터 통념과 같은 답을 갖고 있었다.
- 그런데 화면은 「최적 (채권 35%, 주식 100%)」을 적고 있었다. 원인은 **동률**이다 —
  경제 관점 σ 는 `Xe = w채(1−h채) + w주(1−h주)` 하나로만 결정되므로 같은 Xe 를 만드는
  조합의 σ 가 **소수 6자리까지 동일**하고, 격자 `argmin` 이 그중 스캔 순서상 먼저 만난
  구석을 골랐을 뿐이다. (채권 62% / 주식 2.8%)도 똑같이 「최적」이었다.

**교훈**: 목적함수가 축 하나로 붕괴하는지 먼저 확인하지 않고 `argmin` 결과를 그대로
화면에 적으면, 무한한 동점 중 임의의 한 점이 「모형의 결론」으로 읽힌다. 자세한 구조는
`CLAUDE.md`「헤지 레버의 자유도는 실질 1개다」.

> 권고의 방향은 유지되어도 **최적점 수치는 달라진다.**

### 7.6.1 화면 동선 재설계 — 요약·시뮬레이션 콘솔 (2026-08-05 사용자 확인·승인)

사용자가 실사용자(자산배분담당·운용담당)의 **메인 용례 두 가지**를 확정했다:
① 최적 배분·최적 헤지가 얼마인지 조회 ② 배분·헤지를 마음대로 조정하며 수익·위험
변화를 시뮬레이션. 기존 화면은 계산은 있는데 동선이 이 둘에 맞지 않았다 —
최적 헤지가 레버 **문단 속**에 있었고, 배분 조정은 수기입력 오버레이 왕복이었다.
"A(요약 재배치)+B(즉시반영 콘솔)" 범위로 승인받아 반영했다:

- **`#alloc-summary`** — 현재 vs 참고치(배분 6·헤지 채/주·Xe·수익·위험·듀레이션 갭)
  한 표. **부분해임을 명시**("동시 최적해가 아닙니다" — 동시해는 통화축 확장 후).
- **콘솔** — 배분 8칸(회계 구분 그대로 — 경제 6칸으로 받으면 장부/시가 분할 규칙을
  지어내야 해서 자의성) + 헤지 슬라이더 2개, **즉시 반영·저장 안 함**. 저장/되돌리기는
  명시적 버튼. 조정 중에는 배지 + 요약에 기준(저장값) 행 + 투자선에 ×기준/▲조정 마커.
- **합계 가드** — 목표(100−대출)와 다르면 경고. 「잔여→단기자금」은 명시적 버튼이고
  과다 배분은 버튼으로도 못 맞춘다(조용히 맞추지 않는다).
- 헤지 슬라이더의 **자동 저장을 제거**했다(예전엔 놓는 순간 저장). 승인 ②(슬라이더
  2개 분리)는 그대로다 — 바뀐 것은 저장 시점뿐이다.
- 남은 것: **C(동시 최적 표시)** — 통화축 확장과 한 묶음.

### 7.7 자산배분 2차 재설계 — 벤치마크 직접 투입 + MV 이중 관점 (2026-08-11 합의, 시안 전)

사용자 판정: **"자산배분·환헤지가 아무리 생각해도 너무 보기 어렵다, 실효성 있게 활용하기

배분"**으로 줄이는 것. §2 순서에 따라 아직 **논의 단계**이며 시안·구현 전이다.

**합의된 설계 (사용자 확정):**

  현행 원천 10개(벤더 프록시)를 **데이터층에서 대체**한다.
- **mean-variance 최적 배분(환헤지 비율 포함)을 직접 표시**하고, 사용자가 비중을
  바꾸면 기대수익·변동성 변화를 **즉시** 보여준다. UI 는 **드래그 바**(사용자 제안).

  상한에 붙을 것을 사용자도 예상하고 수용함. ② **경제적 실질 관점** — 장부가 자산도
  전부 시가 변동성으로. 같은 벤치마크, 다른 위험 정의.
- **제약**: 장부가 성격 자산(장부가 국내채권 + 장부가 해외채권 + **단기자금 포함**)
  **합산 ≤ 70%** (사용자 확정 — 각각이 아니라 합산). 나머지 자산군은 상하한 없음.
  공매도 금지(전 자산 ≥ 0)는 기본. 70 이라는 수는 **사용자 내규**이므로 코드 하드코딩
  대신 수기입력 디폴트로 둘지 시안에서 확인할 것(공개 저장소 — §7.5 원칙과 동일 쟁점).
- **기대수익 출처**: 전망 모델(모델 랩)이 오기 전까지는 **중립 앵커**(동일 샤프류)를
  디폴트로 하고 화면에 "기대수익 출처"를 항상 명시. 과거 평균수익률을 그대로 쓰지
  않는다(노이즈 → 극단해). 전망 모델이 완성되면 그 출력이 이 자리에 꽂힌다 —
  여러 이론·애널리스트 전망을 통합하는 **전망 레이어는 별도 구축**(사용자 계획, §8).

**아직 열려 있는 것 (벤치마크 업로드 때 확인):**

- 벤치마크 스펙: 자산군별 **TR(총수익) 지수, 월별 이상, 이력 10년+ 권장**.

  사실상 6개, 회계 구분은 계산 층이 처리).

**재사용되는 것**: 즉시반영 계산 엔진(`allocEngine`)·Xe 붕괴 구조·조작/저장 분리·

#### 7.7.3 디스무딩 대신 **기관 방식(주식·채권 반반 팩터 대입)** — 실측으로 권고가 뒤집혔다

에이전트의 최초 권고는 ①(Geltner)였다. 사용자가 **기관 자산배분담당의 현행 방식은
「대체투자 위험 = 주식·채권 반반」**이라고 알려 와 둘을 실측 비교했고, **기관 방식이
낫다는 결론**이 나왔다. 최초 권고는 철회한다 — 아래가 그 근거다(전부 실행 확인).

**① Geltner 보정은 실제 의사결정을 거의 못 바꾼다.** 기대수익 가정이 필요 없는 장기
최소분산 배분(시가 5개 자산)에서 대체투자 비중:

| 대체투자 처리 | σ(연) | 최소분산 비중 | 포트 σ |
|---|---:|---:|---:|
| 관측 그대로 | 1.41% | **64.0%** | 1.19% |
| Geltner 보정 | 1.99% | **61.3%** | 1.52% |
| 기관 방식(해외주식·해외채권 반반) | 7.98% | **0.0%** | 2.48% |

σ 를 40% 올려도 비중이 64%→61% 로만 움직인다. **원인은 σ 가 아니라 상관**이다 —
관측 상관이 −0.07~−0.23(전부 n=54, SE≈0.14 → 0 과 구분 불가)이라 「저변동·무상관」
자산이 되어 최적화가 몰빵한다. 디스무딩은 자기상관만 없앨 뿐 이 상관을 고치지 못한다.

**② 디스무딩이 원리적으로 회복할 수 없는 것이 있다.** 역필터는 평가가 **늦게** 반영되는
지연을 되돌린다. 그러나 감정평가가 시장 스트레스를 **애초에 기록하지 않았다면** 어떤
필터도 없는 분산을 만들어내지 못한다. 실제로 보정 후 σ 1.99% 는 **시가 국내채권
2.12% 보다도 낮다** — 대체투자 북의 경제적 위험 수치로 볼 수 없다.

**③ 기관 방식은 σ 와 상관을 한꺼번에, 구조적으로 정한다.** 대체투자 행·열을
`0.5·주식 + 0.5·채권` 노출로 두면 상관이 자동으로 일관되게 따라온다(+0.52~+0.96).
이것은 임의 대입이 아니라 **룩스루 팩터 매핑**이며, 보고 계열이 시장가격 계열이 아닌
자산군에 쓰는 표준 도구다. 무엇보다 **북에 무엇이 들어 있는지는 기관이 알고 우리는
모른다** — 반반이라는 판단은 그 지식을 담은 것이고, 우리 디스무딩은 신뢰할 수 없는
지수가 보여 주는 것만 담는다. (참고: 디스무딩한 자기이력을 팩터에 회귀하면 β=−0.04 로
사실상 0 이지만, 스무딩된 계열에서는 β 가 0 으로 눌리는 것이 정상이라 **이 데이터는
반반 가정을 지지하지도 반박하지도 못한다**. 그래서 판단의 문제이고, 기관 판단이 이긴다.)

**④ 정치적으로도 새 싸움을 만들지 않는다.** 이미 기관의 현행 방식이므로 대시보드가
방법론을 새로 강요하는 모양이 되지 않는다. 다만 방향은 반대임을 알아 둘 것 —
기관 방식이 대체투자에 **훨씬 불리**하다(최소분산 0% vs 디스무딩 61%). 단 이 0% 는
기대수익 0 가정·무제약 최소분산의 산물이라 실제 최적해와 다르다.

**구현 시 반드시 지킬 것 4가지:**

1. **순수 대입은 특이행렬을 만든다.** 대체투자가 기존 두 자산의 정확한 선형결합이 되어
   공분산 순위가 결손된다(실측 최소고유값 −1.8e−18, 조건수 1e299 → QP 해 불정).
   **고유위험(idiosyncratic) 분산을 반드시 더할 것** — 디스무딩한 자기이력을 팩터에
   회귀한 잔차 σ 로 추정하면 1.97%, 합성 σ = √(7.98² + 1.97²) = **8.22%** 이고
   최소고유값이 1.32e−04 로 회복된다. 이 값이 「디스무딩을 버리지 않고 쓰는 자리」다.
2. **어느 주식·어느 채권인지가 최대 미결 레버다** — 해석에 따라 σ 가 **6.96%~18.00%**
   (2.6배): 국내주식+국내채권 17.15% / 해외주식+해외채권 7.98% / 국내주식+해외채권
   18.00% / 해외주식+국내채권 6.96% / 주식블렌드+채권블렌드 11.77%.
   **자산배분담당에게 확인할 것.** 권고 기본값은 기관 자신의 주식·채권 배분 비중을
   따라가는 블렌드(포트폴리오와 내적 정합).
3. **반반 비율(0.5/0.5)은 코드에 박지 말 것** — 내규성 방법론 선택이므로 헤지비율
   밴드와 같은 취급(화면 입력 + 중립 디폴트 + localStorage). 60/40·70/30 민감도도 돌 수 있어야 한다.
4. **자기이력 디스무딩 값(1.99%)은 진단으로 계속 게시**한다. 활성값은 아니지만 (a) 검증
   흔적이고 (b) 8.22% 와의 격차가 좁혀지면 벤치마크 성격이 바뀐 신호다.

**남은 한계**: 이 벤치마크가 감정평가 기반인지 혼합 지수인지 **구성 방식을 모른다.**
§7.7.2 의 진단 표는 유효하다(스무딩 존재는 확정). 바뀐 것은 **대응 방법**이다.

#### 7.7.5 시변·창 민감도 카드 — λ-효용 MVO (2026-08-11 사용자 지시, 구현 완료)

지시: "시변(Time-varying) 또는 표본 창을 바꿔 가며 최적화에 따른 자산군별 비중
변화를 볼 수 있게. **λ=1 기본**, 커스터마이징은 나중에." 구현:

- **데이터**: `bm.py` 가 `cma.tv` 로 길이(1·2·3년…)별 **롤링 월말 공분산**을 게시
  (실데이터: 1년 43시점 / 2년 31 / 3년 19, alloc.json 27→121KB). 가중치 경로가
  아니라 공분산을 싣는다 — 경로를 파이프라인이 굳히면 λ·기대수익 키인·매핑·제약
  커스터마이징이 전부 죽는다(데이터/모형 분리). 롤링 **평균은 싣지 않는다** —
  실현 평균을 μ 로 쓰는 문을 열지 않는다. 검증: 롤링 종점 = 같은 길이의 고정 창
  (반올림까지 동일 — 테스트가 강제).
- **화면**: `#alloc-tv-card` — 「시변(롤링)」 모드는 자산군별 비중 경로 차트+표,
  「창 민감도」 모드는 창별 최적 배분 표. 목적함수는 max μ'w − (λ/2)w'Σw,
  **λ=1 소수 단위** (`st.mvo_lambda` — UI 노출은 차기). μ·밴드·그룹 한도·매핑·
  헤지는 현재 설정 고정이라 **움직임은 위험 구조(σ·상관) 변화만 반영** — 화면이
  이를 명시한다. 요약의 ①②와 다른 세 번째 참고축임도 명시.
- **주의(프로브가 실측)**: 밴드에 붙은 자산은 표본이 바뀌어도 못 움직인다 —
  λ=1 에서 비중이 평평하면 코드 결함이 아니라 밴드 상한이 물고 있는 것이다.
  프로브 `cmaTv` 가 λ 단조성·σ↑→비중↓ 방향성·밴드 붙음 구분을 실행으로 확인.

표기 + 툴팁으로 바꾸고, 비어 있으면 그 값이 그대로 공분산에 들어간다는 사실은
기존 프로브(행렬 원소 = 벤치마크 공분산 손계산)가 이미 고정하고 있다.

**저장된 옛 μ 가 새 디폴트를 덮던 문제(2026-08-12 사용자 발견 — 대체투자 지분형이
대출형과 같은 4.39 로 보였다).** 실행으로 확인: 저장분을 지우면 6.86/4.39 로 정상,
옛 저장분이 있으면 4.39/4.39 로 굳는다. 원인은 `allocState` 가 "사용자가 키인한
값"과 "우리가 채운 디폴트"를 구분하지 못해, 한 번 저장된 뒤에는 파이프라인 디폴트를

μ·북일드·σ 키인만 게시 디폴트로 되돌린다(비중·밴드·헤지는 건드리지 않는다).

#### 7.7.12 λ(위험회피계수) 선택 UI + 역산 앵커 (2026-08-12 지시, 구현 완료)

**지시**: "람다도 선택할 수 있게 해줘. 람다는 통상적으로 보험사가 자산배분할 때
어떻게 설정하는 게 맞는 거야?"

**구현**: 시뮬레이터에 λ 키인(`#alloc-lambda`) + 「현재 위험과 같은 λ 찾기」 버튼.
λ 는 모형 입력이라 즉시 저장(비중만 시뮬레이션이라는 기존 분리 승계). 시변·창
민감도 카드도 같은 `st.mvo_lambda` 를 쓰므로 한 곳만 바꾸면 두 카드가 함께 움직인다.

**「권장 λ」를 코드에 박지 않은 이유 — 자의성 금지 규약의 연장.** λ 는 관측되지
않는 **선호 모수**다. 교과서·실무에 흔히 인용되는 값(예: Black-Litterman 계열이
시장 포트폴리오에서 역산하는 δ ≈ 2~3, 소수 단위)은 **총자산 투자자**를 전제한
것이라, 자본규제·부채가 지배하는 보험사의 자산-only 최적화에 그대로 옮기면 근거가
없다. 그래서 숫자를 고르는 대신 **관측 가능한 앵커를 역산**해 준다:

- `allocLambdaForSigma(E, σ_target)` — 최적해의 위험 σ\*(λ) 가 λ 에 대해 **단조
  감소**하는 성질을 이용한 **로그 이분법**(격자·초기값·임의 상수 0개). 기본 탐색
  구간 [0.02, 500], 24스텝.
- 버튼은 σ_target = **현재 배분의 위험**으로 호출한다 → "지금 감수 중인 위험 수준을
  그대로 유지한다면 배분은 어디로 가야 하나"를 묻는 역최적화 앵커가 된다.
- 목표 위험이 구간 밖(밴드 제약상 도달 불가)이면 `bounded: "low"|"high"` 를 돌려주고
  화면이 **사유를 적는다** — 끝값을 조용히 "정답"이라 쓰지 않는다.

**단위 주의**: λ 는 **소수 단위**(μ 소수, Σ 소수²)다. λ=1 이면 위험 5%→6% 이동을
기대수익 **+0.06%p** 로 교환한다(계산: (0.06²−0.05²)/2 = 0.055%p). 즉 λ=1 은
상당히 공격적인 설정이고, 보수적으로 가려면 수십 단위가 필요하다 — 화면 문구에
이 환산 예시를 적어 두었다(감각 없이 숫자만 바꾸는 것을 막기 위해).

**사용자 질문 「보험사는 λ 를 어떻게 정하는 게 맞나」에 대한 답변 요지**(별도 심층
질의용 프롬프트를 사용자에게 전달함): 업계 표준 상수는 없고, 실무는 λ 를 **직접
고르지 않고 관측 가능한 제약에서 역산**한다 — ⓐ 위험예산(목표 변동성·Surplus-at-Risk)
을 맞추는 λ ⓑ 현재 정책 포트폴리오를 최적으로 만드는 λ(역최적화 = 이 버튼) ⓒ K-ICS
가용자본·요구자본 비율 하한을 제약으로 걸고 λ 는 그 제약이 물릴 때까지 낮추는 방식.
**차기 검토**: 자산-only λ 대신 **잉여(surplus) 기준 목적함수**(자산−부채 변동성)로
갈지 — 그쪽이 보험사 문헌의 정공법이고, 이미 있는 듀레이션 갭 카드가 그 방향의 씨앗이다.

#### 7.7.13 헤지 2트랙 — 최적(배분+헤지 동시) vs 시뮬 + 통화별 분해 (2026-08-12 지시, 구현 완료)

**지시**: "자산배분에서 최적/시뮬 2가지가 나오는 것과 매칭되게 환헤지 비율도 2트랙으로 —
최적 환헤지와 시뮬 환헤지를 선택할 수 있게. 통화별 환헤지 비중도. 이전 지시와 상충되면
먼저 얘기해줘."

**상충 점검 결과(사용자에게 보고)** — 지시를 막는 상충은 없고, 표기 제약 둘만 있다:
① 「최적 환헤지 비율」이라는 **한 쌍의 숫자는 존재하지 않는다** — Xe 붕괴(같은 Xe 는
위험이 정확히 같음, §5.3에서 사용자 본인이 발견한 버그의 원인) 때문에 최적은 Xe\* 하나이고
쌍은 현재값 최근접 **대표점**으로만 적는다(기존 규약 그대로 승계).
② **통화별 「최적」 헤지는 지금 모형에서 계산 근거가 없다** — 환축이 달러원 하나라서
(통화축 확장 백로그 전). 통화 구성으로 **펼친 분해 표시**까지만 하고 그 사실을 화면에 밝힌다.

**구현**:
- `allocJointOpt(E, st)` — 배분+헤지 **교대(블록 좌표) 최적화**. 정당성: 좌표를 (w, Xe)로
  잡으면 노출 벡터가 선형 → 목적함수 결합 볼록 → w-스텝(λ-효용 QP)·Xe-스텝(폐형 2차식
  최소) 교대가 전역해로 수렴. μ 키인 최종치(§7.7.10 — 캐리 미가산)라 Xe-스텝 = 위험최소가
  효용최적과 일치. 시작점 = 현재 슬라이더, 최대 6회, 수렴 플래그 반환. μ 키인을 비우면
  폴백 μ 에 캐리(h×cost)가 붙어 Xe 만으로 효용이 안 닫히는데, 그 경우에도 헤지 스텝은
  기존 hq 와 같은 위험최소 기준을 쓴다(요약·레버와 같은 관례 — 새 기준을 만들지 않음).
- 엔진 w-일반화: `xeQuadW(w)`/`xeOfW`/`hedgePairForXeW` — 기존 w0 전용 메서드는 위임으로 유지.
- 헤지 슬라이더가 설정 구역 → **시뮬레이터 패널로 이사**(step 5→1). 즉시 반영·저장 안 함
  규약 그대로. ① 카드에 「헤지 슬라이더를 최적으로」 버튼(쌍을 ②에 얹기 — 저장 안 함),
  ② 카드에 "이 배분의 위험최소 Xe" 참고 문장(요약 hq 와 같은 계산).
- `allocCcyHedgeRows()` — 통화별 분해(접이식 표, 두 트랙 나란히): 노출 = w채×통화구성(채권)
  + w주×통화구성(주식), 헤지/미헤지 분리. 통화 구성은 수기 입력 우선·벤치마크 폴백이고
  출처·커버리지를 행 밑에 적는다. 슬리브 안 균일 비율이라는 사실도 화면에 명시.
- 환율 축 부재(fxLive=false): 헤지 무력(전 조합 동점)을 카드에 적고 배분만 최적화.

**검증**: 프로브 `hedgeTracks` 15측정(수렴·대표점 정합·동시해 ≥ 부분해·밴드 준수·슬라이더
이동·비저장·통화 분해 손계산·무력 표기) + pytest 2건. 요약 표의 헤지 참고치(현재 배분
기준 hq)와 ①의 헤지(최적 배분 기준)는 **다른 기준점**이며 각자 라벨이 그 사실을 밝힌다.

#### 7.7.14 환헤지 비용 모니터 — 미국채 투자 메리트 + 위험수준 연동 (2026-08-12 지시, 구현 완료)

**지시**: "관심 종속변수 중 하나가 환헤지 비용(스왑레이트). 위험수준과 환헤지 비용의 관계를

  현재 스냅숏 + 자기 이력 백분위. 임의 계수 0(전부 항등식). 시리즈 없으면 `active:false`

- `panel.py VARS` 에 「환헤지 비용 (3개월 스왑레이트)」 추가(30→31) — 위험수준(stress/vuln)

- `#hedge-merit-card`(환헤지 화면): 타일 4개(비용·헤지 후 UST·국고·스프레드+백분위) +
  주간 차트(헤지 후 UST vs 국고 vs 스프레드) + **위험수준 연동 문장** — 관계분석 패널의
  주간 stress 점수와 **13주 변화** 상관(수준 상관은 추세 탓에 허구 상관이 되기 쉬워 변화로
  잰다)을 적고, 정식 통계는 관계분석으로 안내. 패널이 없으면 문장 대신 링크로 물러난다.

**검증**: 프로브 `hedgeMerit` 12측정(항등식 손계산·부호 열쇠·만기 구분·위험 역행 합성

#### 7.7.15 카드 위계 전환 + 헤지 최적 마커 (2026-08-12 지시, 구현 완료)

**지시 둘**: ① "최적포트폴리오·시뮬레이션 카드에서 위험이 수익률보다 위에 더 크게 나오는데,
수익률을 더 크게 위험을 더 작게." ② "헤지 슬라이더를 최적으로를 눌러도 헤지 비율이 바뀌지
않는다. 최적이 계산이 안 되는 상황이냐? 계산된다면 자산비중처럼 환헤지도 최적을 표시해줘."

**② 진단 — 최적은 정상 계산된다(실데이터 실행 확인).** 디폴트 상태에서 `allocJointOpt` 는
(채권 90% / 주식 47%), Xe 8.01%, σ 7.48% 를 낸다. DOM 경로로 버튼을 눌러 슬라이더 값이
`[90,90] → [90,47]` 로 바뀌는 것까지 확인했다. 사용자가 무반응으로 본 원인 둘:
- **채권 슬라이더는 원래 안 움직인다** — 최적 배분에서 **해외채권 비중이 0** 이라
  그 슬리브의 헤지비율은 Xe 에 기여가 없다(위험 무영향). `hedgePairForXeW` 가 현재값을
  그대로 두는 것이 옳은 동작이다(임의로 움직이면 그게 거짓 정보).
- **헤지 밴드를 좁게 저장했으면** Xe\* 가 경계로 잘려 최적쌍 = 현재값이 된다.
  실측: 밴드 90~100 이면 최적쌍이 (90/90) 으로 현재와 같다.
즉 결함은 계산이 아니라 **화면이 이유를 말하지 않은 것**이었다.

**구현**:
- `allocJointOpt` 에 진단 필드 추가: `inertBond`/`inertEq`(그 슬리브 비중 ≈ 0),
  `xeFree`(무제약 위험최소 Xe), `bandBinds`. 카드가 이 셋으로 사유 문장을 만든다
  (비중 0 · 밴드 물림 · 이미 대표점).
- 헤지 슬라이더를 `.sim-bar-wrap` 으로 감싸고 `.sim-opt-mark`(▼) 부착 — 비중 막대와
  같은 방식. 단 title/aria 에 **「대표점」** 을 명시하고, 무영향 슬리브는 마커를 **숨긴다**.
- 카드 위계: 기대수익 19px(시뮬)·20px(참고치) 위, 위험 13px 아래. 표본오차는 위험에
  붙는 값이라 위험 줄로 함께 내렸다. **라벨 문자열은 불변**(문자열 검사 보호).

**하네스가 잡은 회귀 1건** — 헤지 슬라이더가 `.sim-bar-wrap` 을 공유하게 되자 「비중 막대
7개」를 세던 프로브가 9개를 셌다. 서로 다른 축을 한 수로 묶으면 어느 쪽이 깨져도 그 검사가
거짓말하므로, 비중 카운트를 `.sim8-row` 안으로 좁히고 헤지 쪽은 `hedgeTracks` 가 따로 잰다.

**검증**: 프로브 `cardHierarchy` 8측정(DOM 순서·font-size 실측 — 문자열이 아니라 크기를
잰다) + `hedgeTracks` 확장 6측정(마커 위치·대표점 표기·무영향 숨김·사유 문장·밴드 물림)
+ pytest 2건.

#### 7.7.16 CMA 표본을 μ 기준일에 맞춰 컷 + 헤지 무반응 사유 재점검 (2026-08-12)

**지시**: "자산군별 디폴트 위험값을 25년 12월까지만 계산해줘. 기대수익률이 25년 12월 말
기준이거든."

**왜 옳은 요구인가**: μ 는 사용자 키인(2025-12 빈티지), σ 는 파이프라인이 최신(2026-07)까지
계산하고 있었다. 최적화는 그 시점 불일치를 **조용히 삼킨다** — 같은 표의 두 수가 서로 다른
세계의 값인데 화면 어디에도 그 사실이 없었다.

**구현** (`bm.CMA_SAMPLE_END = "2025-12-31"`):
- 컷을 `rets` 단계에 건다 → **창·롤링(tv)·디스무딩 α 전부**가 컷 이후를 보지 않는다.
  α 를 나중에 자르면 보조축이 미래를 훔쳐본다(look-ahead) — 원천에서 자르는 이유.
- `coverage` 는 컷 전 **실제 가용 구간**을 그대로 둔다(두 수가 다른 것이 정상).
- 게시: `sample_end` + `data_last`. 화면(위험 원천 줄)이 둘을 함께 적는다.
- **μ 빈티지와 한 몸** — μ 갱신 시 이 상수도 함께 옮긴다.

**실측 영향**: 창은 1·2·3·전체(48개월, 2022-01~2025-12). **5년 창은 안 열린다**(공통 표본
48개월) — 기본값 `cma_win:"5"` 는 기존 폴백대로 최장 창으로 물러나고 화면에 그대로 보인다.
σ 변화(전체 창): 시가 국내주식 **33.54% → 21.88%**, 시가 해외주식 12.95% → 11.64%,
시가 해외채권 5.01% → 5.24%, 시가 국내채권 2.48% → 2.60%. 국내주식 급감은 2026년 이상
변동월이 빠진 결과이고, 그 구간이 KOSPI 실제 변동이라는 점은 §7.7.12 에서 확인했다.
**최적 헤지도 이동**: 컷 전 (채권 90/주식 47, Xe 8.01%) → 컷 후 (채권 90*/주식 0, Xe 15.00%,
노출 상한 구속). 컷은 CMA 층에만 걸었다 — 벤더 프록시층은 대조용이고 자체 표본을 표시한다.

**같은 라운드의 재점검 — §7.7.15 표기 결함 2건(진단 워크플로가 발견)**:
1. **`bandBinds` 오표기**: 헤지 밴드가 중립인데도 「헤지 밴드가 물고 있습니다」가 나갔다.
   실제 구속은 **해외자산 비중 자체**(헤지 0% 여도 Xe ≤ w채+w주)였다 — 사용자를 밴드
   완화라는 **틀린 조치**로 보내는 안내다. `bandBinds`(내규 밴드) / `capBinds`(노출 상한)를
   분리하고 각자 다른 문장을 쓴다. 판정 기준도 xe → **xeFree 가 [xeLo,xeHi] 밖인지**로
   바꾸고 허용오차를 상대값으로 뒀다.
2. **비수렴 은폐**: λ=100 에서 `converged:false`(반복 상한)인데 UI 가 그 플래그를 읽지
   않았고, 잔차 8.1e-5 가 절대 허용오차 1e-9 를 넘어 **아무것도 안 무는 상태에서 밴드
   경고**가 떴다. 이제 근사임을 화면에 적는다.
3. 부수: 이미 최적이면 버튼이 **비활성 + 「이미 최적」** 라벨(눌리는데 무동작인 것이 고장
   신호였다), 무영향 슬리브 헤지 숫자에 `*` (최적값이 아니라 현재값 반사임을 숫자 자리에서).

**검증**: pytest 계약 1건(창·롤링이 컷을 넘지 않음) + 프로브 `cmaSampleCut` 6측정 +
`hedgeTracks` 확장(band/cap 분리·무동작 버튼 상태).

#### 7.7.17 환노출 구속 귀속을 한 함수로 — 배타 판정 제거 + 네 자리 통합 (2026-08-13)

**출발점**: §7.7.16 을 배포한 뒤 그 변경분을 적대적 재검증에 걸었다(4개 렌즈 → 지적
27건 → 반증 통과 5건). **컷 로직(`bm.py`)은 전부 반증됐고**, 살아남은 것은 모두
§7.7.15~16 의 **헤지 구속 표기** 쪽이었다. 즉 "μ 기준일 컷" 자체는 문제가 없었고,
같은 라운드에 얹은 표기 수정이 불완전했다.

**결함 1 — 배타 판정.** `if (xeHi < openMax) bandBinds = true; else capBinds = true;`
는 「밴드가 조금이라도 좁혔는가」만 보고 「밴드를 중립으로 풀면 닿는가」를 보지 않는다.
그래서 **밴드 하한(내규 최소헤지)이 있으면서 동시에 무제약 최적 Xe 가 해외자산 비중보다
큰** 상태에서 밴드 문장만 나갔다 — 사용자가 지시대로 밴드를 중립까지 풀어도 목표에
못 닿는, §7.7.16 이 없애려던 바로 그 오귀인이다. **실제 게시 페이로드로 직접 재현**했다:
λ×채권헤지하한 28조합 중 **6조합**. 예 λ=30·하한 10% → 해외비중 5.00%, xeHi 4.50%,
xeFree 11.08% 인데 밴드 문장만. 밴드를 중립으로 풀면 xeHi 는 4.50→5.00 으로 0.5%p
움직일 뿐이다(11.08% 에는 영영 못 간다).

**결함 2 — 한 자리만 고침.** 이 판정을 쓰는 화면이 **넷**인데 §7.7.16 은 ① 시뮬레이터
최적 카드만 고쳤다. ② 요약표 `#alloc-summary` · ③ 레버 문단 · ④ 헤지 곡면 오버레이는
분리 이전의 단일 플래그(`|xeBand − xeFree| > 1e-9`, 절대오차)를 그대로 써서 **중립
밴드에서도** 「헤지 밴드가 물고 있습니다」를 단언했다. 요약표는 화면 규약상 「그래서
얼마인데?」의 답 자리라 여기의 오귀인이 가장 비싸다.

**결함 3 — 하한에 상한 문안.** `xeFree < 0` 로 아래쪽이 잘릴 때도 capBinds 가 서는데,
그 문장은 "해외자산 비중(Y%)이 환노출의 상한"이라는 상한 전용 문안이었다. 실제 구속은
「오버헤지 불가(Xe ≥ 0)」이고 Y% 는 그 구속과 무관하다 — 성립하지 않는 설명이다.
(현재 실데이터에서는 corr(시가 해외채권, 달러원) < 0 이라 발현하지 않지만, 표본·비중이
바뀌거나 통화축이 확장되면 나온다.)

**수정**: `allocXeBinds(wF, xeLo, xeHi, xeFree)` + `allocXeBindNotes(b)` 두 함수 신설.
판정을 **집합**으로 바꿨다 — `xeNeutral = clamp(xeFree, 0, wF)`(밴드를 중립까지 풀면
갈 수 있는 곳), `xeBand = clamp(xeFree, xeLo, xeHi)`(실제 밴드에서 갈 수 있는 곳)를
두고 `capBinds = xeNeutral ≠ xeFree`(구조적), `bandBinds = xeBand ≠ xeNeutral`(밴드가
그 위에 더 얹은 몫). 둘 다 참일 수 있고 그때 두 문장이 함께 나간다. 밴드 문장은
**완화하면 얼마가 움직이는지 두 수를 적는다**(조치의 크기를 숨기지 않는다).
`side` 로 상·하한을 갈라 하한에는 「오버헤지 불가」 문안을 쓴다.
**네 자리가 전부 이 두 함수를 부른다.**

**검증**: 프로브 `hedgeTracks` 54측정 전원 통과(신규 20측정 — 판정 단위 4상태×2방향,
동시 구속에서 두 문장, 밴드 문장의 이득 수치, 네 자리 정합, 옛 문구 부재) + pytest 2건.
프로브 시나리오를 만들 때 실측으로 배운 것 둘: **해외채권 밴드를 `[0,2]` 로 두면 최적화가
그 슬리브를 0 으로 보내 버려 채권 헤지 하한이 아무것도 좁히지 못한다**(동시 구속이 성립
안 함 — `[2,2]` 로 고정할 것). **오버레이는 해시만 바꿔서는 안 열린다**(`handleHash()`
가 진입점이라 프로브는 `openAllocDetail("hedge")` 를 직접 부른다).

#### 7.7.18 「표본 종료」는 요청한 컷이 아니라 도달한 끝 (2026-08-13)

**발견 경로**: §7.7.17 배포 후 남은 시간에 §7.7.16 의 컷 표시를 다시 실행해 봤다.
적대적 재검증에서 이 계열의 지적이 여러 번 나왔다가 매번 반증됐었는데(전부 "현재
데이터에서는 발현하지 않는다"가 이유였다), **세 갈래를 직접 렌더시켜 보니 한 갈래가
실제로 거짓말을 하고 있었다.**

**문제**: 화면이 「표본 종료」로 적는 날짜가 상수 `sample_end` 였다. `asof`(실제로
도달한 표본 끝)와 갈리면 ① 표본이 닿지도 않은 달을 「표본 종료」라 쓰고 ② 하지도 않은
절단을 했다고 단언하며 ③ **μ·σ 시점이 어긋난 사실을 숨긴다.** ③ 이 핵심이다 —
§7.7.16 의 존재 이유가 정확히 그 어긋남을 드러내는 것인데, 어긋났을 때 오히려 숨겼다.

**왜 「발현하지 않는다」가 안심할 근거가 아닌가**: 갈리는 경로가 `CLAUDE.md` 가
지시하는 **정상 유지보수 순서**다 — "μ 를 새 기준일로 갱신하면 이 상수도 함께 옮길 것".
그대로 하면 새 BM 데이터가 오기 전까지 `asof < sample_end` 다. BM 파일은 기관이 직접
올리는 유일한 입력이라 짧은 업로드도 평범하게 일어난다.

**수정**: 화면은 `asof` 를 적고 세 갈래로 문장을 나눈다 — ① 짧음(경고색 `d-up` +
"σ 와 μ 의 시점이 어긋납니다" + 조치 안내) ② 잘림(기존 문장 유지) ③ 자를 것 없음
("자를 데이터가 없었습니다"). 파이프라인도 `asof < cut` 이면 `warn()` 을 남겨
`meta.json` 에 뜬다. **페이로드 의미는 안 바꿨다** — `sample_end` 는 여전히 "요청한 컷"
이고 계약 테스트도 그대로다(표시 계층만 고쳤다).

부수로 잡은 것: `el(tag, attrs)` 는 attrs 를 그대로 `className`/`setAttribute` 한다 —
`class: null` 을 주면 className 이 문자열 `"null"` 이 된다(오류가 안 나고 스타일만
조용히 어긋나는 종류). 조건부 클래스는 **객체를 갈라** 넘길 것. 프로브가 고정한다.

**검증**: pytest 신규 3건(파이프라인 경고 양방향 2 + 화면 세 갈래 1) 포함 전체 통과,
프로브 `cmaSampleCut` 확장 11측정.

#### 7.7.19 BM 계열별 환 기준 — 해외주식은 미헤지였다 (2026-08-17)

**발견 경로**: 외부 AI(노트북LM)에 자문을 구하는 과정에서 「자체 설정 벤치마크가
왜곡됐을 가능성을 점검하라」는 답변이 왔다. 제안된 검정(포트폴리오 대비 R²)은 실제
포트폴리오 수익률이 없어 그대로는 못 돌리지만, **BM 을 시장 표준 지수에 회귀**하는
변형은 가진 데이터로 가능해서 돌려 봤다. 거기서 나왔다.

**문제**: CMA 층이 **모든 해외 BM 계열을 「환노출 제거 기준」으로 읽고** 미헤지분
`(1 − h)` 만큼 `_fx` 를 더하고 있었다. 실제로는 계열마다 다르다 —

| BM 계열 | 회귀 | β(달러원) | R² | 실제 기준 |
|---|---|---|---|---|
| 시가 해외주식 | ~ ACWI + 달러원 | **+1.000** (SE 0.027) | 97.9% | **미헤지** |
| 시가 해외채권 | ~ (−7×ΔUST) + 달러원 | **−0.048** (SE 0.024) | 79.8% | 헤지 |

부표본 4개(전체·2019~2022·2022~·2023~)에서 해외주식 β 는 0.957/1.000/1.023/1.062 로
흔들리지 않는다. 수준으로도 σ(BM 해외주식) 14.10% 가 σ(ACWI×달러원) 13.71% 와 가깝고
σ(ACWI 단독) 15.99% 와는 멀다. **2026-08-17 사용자 확인**: "시가해외주식 BM 은
언헤지야. 우리기관은 주식은 오픈이 기본이야." → **BM 이 자산군별 실제 정책 스탠스대로
산출된다**는 것이 확정됐다(해외채권 100% 헤지 / 해외주식 100% 오픈).

**왜 못 잡았나 — 단순상관으로 판정했다.** 당시 근거는 화면에도 적혀 있던
「corr(시가 해외주식, 달러원) ≈ 0 — 환노출 포함이면 나올 수 없는 수치」였다. 그런데
**ACWI 자체가 달러원과 음의 상관**이라(위험회피 국면에 주가↓·달러↑) 미헤지 원화환산
해외주식은 두 효과가 상쇄돼 단순상관이 0 근처로 나온다. 즉 그 0 은 「환이 없다」가
아니라 **「환이 있다」의 서명**이었다. 갈라내려면 다변량 회귀라야 한다. 방증이 게시
공분산 안에도 있었다 — corr(시가 해외주식 − `_fx`, `_fx`) = **−0.646** 으로, 환을
벗기면 다른 원화 계열(해외채권 −0.589 · 국내채권 −0.612)과 같은 자리에 들어간다.

**영향**: 해외주식 노출이 `w주식` 만큼 이중계상됐다. 현행(he) = 교정(he−1) 이라
**헤지 축이 한 칸 밀려**, 화면의 「완전헤지」가 실제로는 「완전오픈」이었다.
슬리브 σ 는 he=0.9 에서 11.74%(현행) vs 14.58%(교정), 대표 배분의 포트폴리오 σ 는
3.55% vs 3.85%. **방향은 뒤집히지 않았다** — 위험최소 he 가 두 모형 모두 0 이라
§7.6 의 자연헤지 문제가 되살아나지는 않는다(과소계상과 축 이동의 문제다).

**수정**: 계열별 기준 헤지비율 상수 `CMA_BM_H0`(해외채권 1 / 해외주식 0)를 두고
노출을 **`BM + (h₀ − h)·_fx`** 로 바꿨다. h = h₀ 면 보정이 0 이다. `withFx` 의
가드도 `open > 1e-12` → `Math.abs(add) > 1e-12` 로 고쳤다 — h₀=0 계열을 헤지하면
**뺄셈이라 음수가 정상**인데 옛 가드가 조용히 버렸다.

**부수로 드러난 것 — 총 환노출 ≠ Xe.** 매핑 대체투자가 시가 해외주식(h₀=0)을 팩터로
쓰므로 `_fx` 열이 0 인데도 슬리브당 `we/100` 만큼 환을 진다. 헤지 레버가 닿지 않는
몫이라 Xe 에는 넣지 않았고(넣으면 조절 가능한 양이라는 Xe 의 뜻이 깨진다), 엔진
`fxLoadW()` 가 내재분까지 세어 화면이 Xe 와 **구분해서** 적는다. 기본 배분·기본 헤지
(90/90)에서 Xe 2.70% 외에 대체투자가 지는 환이 8.00%p(대체 16% × 매핑 we 0.5) 더 있어
총 10.70%, 즉 **Xe 표기의 3.96배가 실제**였다(2026-08-19 실브라우저 재측정 — 이 절을
처음 쓸 때 적은 「Xe 6.00% 외에 8.00% · 2.33배」는 재현되지 않아 실측값으로 고쳤다.
8.00%p 는 그대로 재현된다). **§7.7.20 이후 이 배수는 `h_alt` 를 따라 움직인다** —
코드 기본값(자리표시자)에서는 대체 몫이 0.80%p 로 줄어 총 3.50% 다. 매핑에 환을 남길지
뺄지는 기관 대체투자 북의 헤지 정책에 달렸고 확인 전까지 **사용자가 말한 그대로**
(「해외주식·국내채권 반반」의 문자 그대로 = 환 포함) 두었다 — 미확인 사항이다.

**검증**: pytest 신규 2건(계열별 h₀ 상수·로딩 사용처·오진 문구 부재 / `fxLoadW` 의
내재분 계상·프록시 null), 프로브 `cmaLayer` 신규 6측정(오픈에서 BM 원본·완전헤지에서
BM 원본·헤지가 주식 위험을 **높인다**·대체 내재 환 0.075·Xe 와의 분리·방법론 문구).
뮤테이션 확인 — 로딩을 옛 `1 − heX` 로 되돌리면 pytest 1건 + 프로브 4측정이 빨간불.

**남은 것**: ① 대체투자 매핑의 환 처리(위) ② 이 발견은 프록시 층과 무관하다 —
그쪽은 벤더 지수(USD 표시)에 `e_usd` 축을 **명시로** 얹는 구조라 애초에 h₀ 모호성이
없다. ③ 같은 방법(다변량 회귀)으로 나머지 BM 계열의 기준도 한 번 훑을 것.

> **①은 §7.7.20 에서 닫혔다** — 사용자 확인으로 대체투자 헤지 정책이 나왔고, 화면
> 입력이 됐다. ②③ 은 그대로 남는다.

#### 7.7.20 대체투자 환헤지 비율 — 화면 입력 (2026-08-19 사용자 지시)

**지시**: "대체투자는 유동적으로 환헤지 하는중이야.. 이것도 사용자가 선택할수있게 하면
좋을거 같아." — 현재 어느 수준으로 걸고 있는지도 함께 알려 줬는데, **그 비율은 운용
정보라 여기 적지 않는다**(§7.6 규약. 화면에서 넣으면 브라우저 localStorage 에만 남는다).

§7.7.19 가 미확인으로 남긴 자리다. 그때 매핑 대체투자는 팩터(시가 해외주식 — h₀=0)를
통해 슬리브당 `we/100` 의 환을 진 채로 두었고, 「기관 대체투자 북의 헤지 정책에 달렸고
확인 전까지 사용자가 말한 그대로」라고 적어 두었다. 그 확인이 왔다.

**두 가지를 사용자에게 물어 정했다** (물어본 이유: 답에 따라 코드 구조가 갈린다).

| 질문 | 사용자 선택 | 코드에 미치는 영향 |
|---|---|---|
| 최적화 레버인가, 모형 입력인가 | **모형 입력** | 즉시 저장(μ·σ·λ 와 같은 칸), 최적 ▼ 없음, **Xe 에 넣지 않음** |
| 지분형·대출형을 나눌 것인가 | **하나로** | 슬라이더 1개. 매핑이 다르면 환노출은 자동으로 달라진다 |

**모형 입력이라는 선택이 Xe 계약을 지킨다.** 대체투자 헤지를 Xe 에 합치면 「최적 헤지쌍」
(`allocJointOpt`)이 위험최소 Xe 를 풀 때 사용자가 이미 정한 비율을 **덮어쓴다** — 지금
그렇게 운용 중이라고 말한 수를 최적화가 조용히 다른 값으로 바꾸는 셈이다. 그래서
`xeOf`/`xeOfW` 는 `h_bond`/`h_eq` 만 보고, 대체투자 몫은 `fxLoadW` 가 세는 **총 환노출**
쪽에만 들어간다. 화면 레버 문단이 두 수를 나눠 적고 어느 슬라이더가 어느 몫을 움직이는지
명시한다(§7.7.19 가 만든 「총 환노출 ≠ Xe」 문장을 그대로 승계·확장).

**산식**: 매핑 행이 `we·해외주식BM + wb·국내채권BM − h_alt·(we)·_fx` 가 된다. 팩터인
시가 해외주식이 h₀=0(미헤지)이라 `we` 만큼 환이 딸려 오고, 그중 `h_alt` 를 헤지해 뺀다 —
순 환노출 `we·(1 − h_alt)`. **매핑이 채권 100%(we=0)면 비율과 무관하게 0** 이고, 이것이
슬라이더를 분류마다 두지 않은 근거다(한 비율이 두 분류에 걸려도 매핑이 다르면 환노출이
자동으로 갈린다). 정본은 `app.js` `cmaAltRows` 의 `mk()`, 디폴트는 `alloc.py`
`DEFAULTS["h_alt"]`.

**코드 디폴트는 기관 수치가 아니라 자리표시자다** — `h_bond`/`h_eq` 와 같은 규약이며,
실제 값은 브라우저 localStorage 에만 남는다(공개 저장소). 디폴트를 바꿔도 무방하고,
화면에서 조정하면 그 값이 정본이 된다. **사용자가 말한 실제 비율을 이 문서나 코드에
적지 말 것** — 아래 실측값의 「기본」은 코드 자리표시자를 가리킨다.

**방향을 손으로 못박지 않았다.** 처음 프로브에 「헤지하면 위험이 준다」를 적었다가 빨간불이
났고, 그게 맞다 — 대체투자는 미헤지 BM 을 팩터로 쓰므로 **자연헤지 성질이 그대로 옮겨
와** 헤지가 위험을 **올릴** 수 있다(직접 해외주식에서 이미 실측된 성질 §7.7.19). 그래서
검사를 둘로 갈랐다: ① 값이 실제로 움직이는가(모형 입력이 계산에 닿는가) ② 방향이 직접
해외주식과 **같은가**. 상관이 뒤집히는 데이터가 오면 둘이 함께 뒤집혀 검사는 그대로
성립한다 — 방향을 상수로 적었으면 데이터 갱신마다 깨졌을 자리다.

**UI 함정 하나**: 헤지 슬라이더와 같은 행·같은 `.sim-bar-wrap` 래퍼를 쓰므로 래퍼를 세는
기존 검사가 2 → 3 으로 깨졌다(§7.7.15 의 `.sim8-row` 한정과 같은 종류). `.sim-alt-hedge`
클래스를 하나 더 달아 갈라냈고, **갈라졌는지 자체도 검사한다**(`altHedgeWrapSeparate`).

**기존 검사 하나가 같이 빨간불이 났는데 코드는 멀쩡했다** — 시변 카드의
`bandPinnedAtLowLambda`. 그 검사는 「λ=1 에서 국내주식이 상한 10% 에 붙어 표본이 바뀌어도
못 움직인다」를 **픽스처로** 적어 두었는데, 행렬이 바뀌자 기본 행렬은 그대로 0.10 이고
**롤링 표본(tv[0].cov[0])만 내부해가 됐다**. 성질(「붙은 자산은 σ 가 변해도 못 움직인다」)은
그대로이므로 **밴드를 눌러 확실히 붙는 상태를 구성한 뒤** 재도록 고쳤고, 자연 상태의 두
값은 진단 키로 함께 싣는다(`natEqAtLambda1`·`natEqAtLambda1Tv`). 같은 부류 — **최적화
결과의 「지금 상태」를 단언하지 말 것. 단언은 성질에 걸고, 상태는 구성해서 만들 것.**

**문서 숫자 하나를 실측으로 고쳤다** — §7.7.19 에 적힌 「Xe 6.00% 외에 8.00% · 2.33배」의

### 7.10 추정일 시나리오 — 금리·주가·환율로 추정일 성과 (2026-08-13)

**지시**: "추정일자를 선택하고… 시장데이터가 우리 data 레포에 있으면 그거 쓰고, 아니면
(미래일 경우) 사용자가 예상값을 수기입력… 금리가 기준일 대비 얼만큼 변했는지를 듀레이션과
곱해서 채권 수익률 변화를, 주식은 주가 변화를 가지고 추정."

**먼저 짚은 것 넷** (사용자가 "틀린 부분이 있으면 먼저 알려줘"라고 했다):
1. **부호가 빠져 있었다** — 금리가 오르면 채권 가격은 떨어진다. `−D × Δy` 다.
2. **캐리가 빠져 있었다** — `−D×Δy` 는 가격 변동만이라 금리 불변 시 수익률이 0 이 된다.
   이 화면의 전제("채권은 수익이 안정적으로 확보된다")와 정면으로 어긋난다.
3. **장부가 채권에 금리 변화를 적용하면 안 된다** — 원가법이라 평가손익이 안 생긴다
   (이 저장소 실측: 장부가 BM 손익변동 σ 0.18%/0.17%. §7.7.11 이 장부가 축을 뺀 이유).
4. **환율 축이 통째로 빠져 있었다** — 원화 기준이면 해외자산은 헤지 안 된 만큼 환이 들어온다.

**사용자 결정**: 캐리는 기준일 수익률에서 자동 환산 · 환율은 넣되 헤지비율 반영 ·
**장부가 국내채권은 캐리만, 장부가 해외채권은 스왑 효과를 반영**("−2% 로 체결했는데 추정일
−3% 로 떨어지면 스왑계약 가치가 올라 수익률이 소폭 상승"). 이 마지막 것이 정확한 지적이고,
**새 모형을 만들지 않고 `hedge.py` 의 회계모형 ④⑤ 를 그대로 쓴다.**

**산식**(`estimate.SCENARIO_MODEL` 이 정본이고 화면이 그대로 적는다):
`추정 기간수익률 = 캐리 + 가격효과 + 환효과 + 스왑 MTM`
· 캐리 = 기준일 연환산 수익률 × 구간일수/365 (주식은 없음 — 가격이 곧 수익)
· 가격효과 = **−**D × Δy (시가 채권) · 지수 변화율(주식) · 0(장부가·대체·대출금·단기자금)
· 환효과 = (1 − h) × Δ환율 (해외자산)
· 스왑 MTM = h × τ × (**−**Δ스왑레이트) — 회계모형 ⑤ 와 같은 부호

**시장 축 6개**(`estimate.json.axes`): 국고 10년 · 미국채 10년 · 달러원 · 스왑레이트 3M ·
KOSPI TR · ACWI. `kind` 가 변화량의 뜻을 정한다(rate=차이, price=변화율) — 화면이 스스로
정하게 두면 금리를 비율로 나누는 사고가 난다. 지수 축은 `indices` 를 **참조만** 한다.
추정일이 데이터 안이면 실제 변화를 조회하고 두 관측일을 밝힌다, 미래면 수기 입력.

**한계(화면이 적는다)**: 1차 근사 — 볼록성 미반영이라 Δ금리가 커질수록 오차가 커진다.
금리 시나리오는 **평행이동** 가정이고 자동 채움은 벤치마크 만기(10년) 변화를 쓴다.
신용스프레드 축은 없다.

#### 7.10.1 재점검 — 적대적 검증이 잡은 5건 (2026-08-13)

§7.9·§7.8.1 배포분을 4렌즈로 감사해 **5건이 반증을 통과**했다. 2건이 CRITICAL 이고
둘 다 이 세션에서 만든 것이다.

1. **CRITICAL — 수기 입력이 자동값 되쓰기에 파괴됐다.** `<input type=number>` 는 `-` 하나만
   친 순간 value 가 "" 라 수기 판정이 풀리고, 되쓰기가 자동값을 도로 넣어 방금 친 문자를
   지운다. **실측: 자동 20.00% 칸에 `-3.5` → `20.0035`, 그대로 저장까지.** 연초 이후
   마이너스 수익률은 흔한 입력이라 상시 재현. → 포커스가 있는 칸은 되쓰지 않고 blur 에서 맞춘다.
2. **CRITICAL — 기준일이 없으면 헤드라인이 「주식 수익 ÷ 전체 규모」였다.** 계수가 없어
   비주식 행이 전부 null 인데 분모는 전체 규모를 그대로 썼다. 참고치가 본치보다 **커지는**
   상태. → 계수가 없으면 그 수를 만들지 않고 사유를 적는다(총 운용수익도 함께).
3. **MAJOR — `a.kpi-link{display:block}` 이 `.kpi` 의 flex+gap 을 덮었다.** 카드 내부 간격
   넷이 사라져 링크 카드 9장이 비링크 3장과 같은 줄에서 16px 어긋났다. `gap` 은 block 에서
   무효라 오류도 경고도 없다. 규칙 주석은 「카드 모양을 유지」라고 적혀 있었다.
4. **MAJOR — "기준일이 전년 연말보다 앞섭니다"가 결코 참이 아니었다.** `estDayCount` 가
   이미 기준일 > 전년 12/31 을 보장한다. 그 가지가 실제로 뜨는 원인은 **축약(5년 초과 구간
   주별)으로 앵커와 기준일 사이에 관측이 없는 것**이라 그 사실을 적는다.
5. **MINOR — 경과일수 NaN 이 `days <= 0` 을 통과했다**(연도 0000 → 전년이 `-1년`).

**검증**: pytest 전량 통과(당시 398건), 프로브 `estimateScenario` 34측정 + `estimateCalc` 65측정.
시나리오는 **전 항을 손계산과 대조**했고(부호 셋 포함), 수정 5건은 실브라우저로 재현·확인했다.

#### 7.11 입력이 곧 연환산 + 기준일·추정일 한 표 (2026-08-13 사용자 지시)

> "사용자가 입력하는 기준일의 수익률이 그 자체로 연환산 수익률이야(주식 제외). 그러니까
> 연환산, 반영수익률은 없애도 되고, 기여도는 아예 막대그래프로 있으니까 빼줘, 그래서
> 기준일과 추정일을 나란히 볼 수있게 해줘"

**규약이 같은 날 두 번 바뀐 자리다.** §7.8 에서는 화면이 입력값에 계수를 곱해 연환산했고,
여기서는 **담당자가 기관 시스템에서 이미 연환산해 들고 온다**는 사실이 확인돼 곱셈이
빠졌다. 곱하면 이중 연환산이다(실측 대비: 1.50% 입력이 3.02% 로 나가던 상태).
정본은 `estimate.ANNUALIZE["input_is_annualized"]` 와 `app.js` 의 `estEngine`.

**곁가지로 드러난 것 — 옛 규약에서 캐리가 자기 정의와 어긋나 있었다.** 문서·화면은
「캐리 = 기준일 **연환산** 수익률 × 구간일수/365」라고 적었는데 코드는 연환산 **전**
원시 입력값을 썼다(배포 화면 실측: 3.02 입력 → 반영 5.46 인데 캐리는 3.02×163/365 = 1.35,
5.46 기준이면 2.44 였어야 한다). 계수 1.81배만큼 과소계상이다. 새 규약에서는 입력값이 곧
연환산율이라 **같은 코드가 맞는 코드가 된다** — 이번 변경이 그 불일치를 없앴다.

**두 열을 잇는 산식(`estimate.SCENARIO_MODEL["cumulative"]`).** 나란히 놓으려면 두 열이
같은 기준이어야 한다. 기준일 값이 연환산이므로 **사용자 규칙의 정확한 역**으로 기간수익까지
되돌린 뒤(× 경과일수 ÷ 365) 구간 4항을 더하고 추정일 기준으로 다시 연환산한다. 캐리가
`r × days/365` 라 대수적으로 정확히 아래가 성립한다:

```
추정일 수익률(연환산) = 기준일 수익률(연환산) + (가격효과 + 환효과 + 스왑 MTM) × 365 ÷ 연초→추정일 일수
```

즉 **두 열의 차이가 곧 시장효과의 연환산분**이고, 그래서 나란히 놓는 것이 뜻을 가진다.
주식은 양쪽 다 연환산하지 않아 차이 = 지수 변화(+환효과)다. 되돌리기를 빠뜨리고
`r + total` 로 더하면 연율과 기간이 섞인다 — 프로브가 이 항등식을 고정한다.

**새로 막은 결함 둘** (둘 다 §7.10 배포분에 있던 것):

- **추정일이 다른 해면 누적을 잇지 못한다.** 그 해 1/1 → 기준일 구간의 수익을 우리는
  모르기 때문이다. 옛 코드는 그때도 `기준일값 + 구간` 을 만들고 **추정일 연도의 짧은
  경과일수**로 연환산했다 — 2026-07-21 → 2027-03-31 이면 ×365/90 = **4.06배**다. 이제
  `crossYear` 로 누적을 비우고 사유를 적으며, 추정 구간은 그대로 낸다.
- **화면이 「듀레이션은 지금 수익률 계산에 쓰이지 않습니다」라고 거짓말하고 있었다.**
  §7.8 당시에는 참이었지만 §7.10 의 가격효과(−D×Δy)가 실제로 쓰기 시작했다. 문장을
  「추정일 가격효과에 쓰입니다」로 고쳤고, 옛 문장이 되살아나면 테스트가 잡는다.

**화면 구조.** 표는 하나이고 헤더가 2행이다 — `자산군 ‖ 기준일(규모·비중·듀레이션·수익률·
출처·운용수익) ‖ 추정일(캐리·가격효과·환효과·스왑MTM·수익률·차이) ‖ 메모`. 폐지된 세 열은
연환산 계수·반영 수익률·기여도이고, 기여도는 바로 아래 막대그래프가 같은 값을 이미 보여
준다. 4항 분해는 **통합 표에만** 그린다(결과 카드에도 그리면 같은 수가 한 화면에 두 번
나오고 한쪽만 고쳤을 때 조용히 갈린다). 시나리오 입력 카드는 표의 오른쪽 절반을 만드는
입력이므로 **표보다 위**로 올라갔다.

**재계산은 한 벌이다** — `recalcAll()` 이 `E`/`S` 를 한 번씩 만들어 표·요약·기여도·축·
결과카드 다섯 곳을 그린다. 따로 돌리면 같은 행의 왼쪽과 오른쪽이 다른 상태로 그려진다.
포트폴리오 「차이」는 행별 가중합이 아니라 **두 헤드라인의 뺄셈**이다(추정 불가 행이
기준일 쪽에만 들어가 「차이 ≠ 추정일 − 기준일」인 세 수가 공존하는 것을 막는다 — 그
왜곡의 원인은 화면이 따로 적는다).

**§7.10.1 의 CRITICAL 하나는 구조적으로 사라졌다.** 「기준일이 없으면 헤드라인이 주식 수익
÷ 전체 규모」는 계수가 필요해서 생긴 문제였는데 계수를 안 쓰게 됐다. 대신 남는 위험
(**수익률이 하나도 없는데 0.00% 를 내는 것**)으로 가드를 옮겼다 — `portBlockedNoRet`.

**검증**: pytest 전량 통과(이 변경으로 +2건), 프로브 `estimateCalc` 77측정 ·
`estimateScenario` 52측정 전부 참. 항등식은 **재연환산 계수가 1 이 아닌 날**(추정일 9/30,
계수 365/273 ≈ 1.337)로 한 번 더 잰다 — 12/31 추정일에서는 계수가 정확히 1 이라
주식/비주식 구분이 수에 드러나지 않아 규약이 뒤집혀도 통과한다(§7.8 의 「2.0 이 아님」
단언과 같은 성격의 자리).

#### 7.12 좌우 2블록 + 추정일 자동계산 + 헤지 선택 (2026-08-13 사용자 지시)

> "가장 먼저 기준일의 자산군, 자산군별 규모, 수익률 입력하는것이 먼저 나오고, 그 오른쪽에
> 병렬적으로 똑같이 추정일꺼를 입력하는걸 만들어줘 … 그 밑에는 기준일과 추정일의 시장지표를
> 보여주는 카드를 만들어줘. 그리고 자료 출처, 쓰는곳은 빼버려 … 환헤지 얼마나 한거인지는
> 개별 (해외자산) 자산군을 클릭해서 사용자가 선택할수있게 … 0~105% 범위"

**추정일 쪽에서 사용자가 치는 것은 규모뿐이다.** 비우면 기준일 규모를 승계한다(화면이
「승계」라고 적고, 승계값은 칸에 **실제로 표시**한다 — placeholder 로만 두면 빈 칸으로
읽혀 다시 넣게 된다). 수익률은 자산군마다 갈리고, 가르는 선은 **가격 축이 있는가**이며
그 판정은 사용자가 자산군을 하나씩 지목해 내렸다:

| 계산(calc, 7개) | 산식 |
|---|---|
| 장부가 해외채권 | 환효과 + 스왑 MTM (원가법이라 가격효과 0, 스왑은 파생이라 MTM 이 난다) |
| 국내주식 | 기준일 수익률 + KOSPI TR 상승률 |
| 해외주식 | 기준일 수익률 + ACWI 상승률 + 미헤지분 환효과 |
| 시가 국내채권 직접·간접 | −D × Δ국고10년 |
| 시가 해외채권 직접·간접 | −D × Δ미국채10년 + 환·스왑 |

| 승계(carry, 4개) | 규약 |
|---|---|
| 장부가 국내채권 · 단기자금 · 대출금 · 대체투자 | 기준일과 동일이 기본, 필요시 수기 |

정본은 `estimate.ROW_MODES`(사유 포함, 화면이 「근거」 열에 적는다)와 `app.js` 의
`EST_SCEN[].mode` 이고, 두 파일이 갈리면 `tests/test_estimate.py` 가 잡는다.
**계산 자산군에는 수기 칸을 만들지 않는다** — 산식이 정본이라 덮어쓸 자리가 없다.

**가중치가 두 벌이다.** 기준일 열은 기준일 규모로, 추정일 열은 **추정일 규모**로 가중한다 —
한 벌로 재면 리밸런싱 효과가 통째로 사라진다. 규모를 직접 넣었으면 「차이에는 시장효과와
리밸런싱 효과가 함께 들어 있다」고 화면이 적는다.

**시장지표 카드는 수준을 나란히 보여 주고 사용자는 추정일 수준을 친다**("국고 10년이 3.50%
가 될 것"). 변화(bp/%)는 화면이 계산해 옆에 적는다 — 수준↔변화 환산을 사용자에게 시키면
금리는 bp, 환율은 % 라 단위를 오갈 때마다 실수가 난다. 구 저장분(변화량 `dlt`)은
`estMigrateLevels` 가 **기준일 수준 + Δ** 로 한 번 이관한다(버리면 넣어 둔 시나리오가
소리 없이 사라진다). 이관 가드는 **`saved.dlt`** 로 본다 — `st.dlt` 는 기본값으로 항상
존재해 그걸로 가드하면 매 렌더마다 다시 돈다(§7.7.11 fold 가드와 같은 함정).

**헤지비율은 자산군을 눌러 0~105% 에서 고른다.** 기관의 현재 정책(해외채권 100% 헤지·
해외주식 100% 오픈)은 운용 정보라 **공개 저장소에 기본값으로 박지 않는다**(사용자 확인) —
고르기 전에는 환효과·스왑 MTM 을 0 으로 지어내지 않고 「헤지비율 미입력」이라고 적는다.
0 으로 채우면 미헤지 자산의 환위험이 통째로 사라진 수가 보고 숫자로 들어간다. 105% 상한은
오버헤지(펀드 NAV 변동에 따른 일시 초과)를 담기 위한 것이고 그 구간에서는 환효과의 부호가
뒤집힌다. 밴드 밖 값은 조용히 받지 않고 밴드 안으로 되돌린다.

**출처·쓰는 곳 열은 접이식으로 내렸다 — 지운 게 아니다.** ACWI 가 PR 이라는 사실과 미국채
부재 사유는 숫자의 뜻을 바꾸므로 화면에서 닿을 수 있어야 한다. **PR 경고만은 겉에 한 줄
남긴다**(배당이 빠진 수가 보고 숫자로 들어가는 자리다).

**실브라우저가 잡은 결함 둘** (셰이드는 못 잡는 성격이다):

- **중첩 `<td>`.** 계산 행의 추정일 수익률 칸을 `el("td", …, c.r2)` 로 감쌌는데 `c.r2` 가
  이미 `<td>` 였다. 브라우저가 중첩을 풀면서 **셀이 하나 더 생겨 그 행만 열이 밀렸다**
  (실측: calc 행 11칸 / carry 행 10칸). DOM 셰이드는 중첩을 그대로 두어 통과시킨다.
- **정상 동작에 경고색.** 「장부가 — 원가법이라 가격효과 없음」 같은 설명 문구까지 빨갛게
  칠해 계산이 잘 된 행(2.33%)이 고장난 것처럼 읽혔다. 판정 기준을 문구 유무가 아니라
  **결과가 비었는가**로 바꿨다.

**프로브가 잡은 회귀 하나** — 출처 열을 내리면서 **묵은 자동값 경고(§7.8.1)까지 사라졌다.**
그 경고는 「출처 정보」가 아니라 「지금 보는 수가 며칠 전 값이다」라는 **값에 대한 경고**라
같이 내리면 안 된다. 「근거」 열로 옮겨 되살렸다.

**다른 해 가드가 승계 행에도 걸린다.** 「기준일과 같다」고 적고 싶어지지만 그때 비교 대상은
*다른 연초*부터 잰 수익률이다. 무엇보다 계산 행은 비는데 승계 행만 수를 내면 한 열 안에 두
규칙이 공존하고 포트폴리오 합계는 비어 있는 모순이 생긴다.

**실브라우저가 잡은 결함 셋째 — 정의되지 않은 CSS 이름은 조용히 무효가 된다.**
헤지 오버레이에 `background: var(--card)` 를 썼는데 이 저장소의 카드면 토큰은
`--surface` 다. 선언이 통째로 무효가 되어 **패널이 투명해지고 글자가 아래 표와 겹쳤다.**
같은 계열로 `class="btn"` 도 없는 이름이었다(실제는 `.btn-ghost`/`.btn-primary`).
CSS 는 오타에 오류를 내지 않아 테스트도 프로브도 못 잡는다 — 그래서
`test_every_css_variable_and_class_actually_exists` 를 붙였다: style.css 의 모든
`var(--x)` 가 정의돼 있는지와 app.js 가 붙이는 클래스가 CSS 에 있는지를 대조하고,
런타임 주입(`--village-img`)·의도적 무스타일(셀렉터 훅 7개)만 목록으로 예외 처리한다.
**그 검사가 기존 결함 하나를 덤으로 잡았다** — `.btn-ghost:hover` 와 시뮬 입력의
`var(--ink)` 는 정의된 적 없는 이름이라(토큰은 `--ink-1/2/3`) 색이 상속으로 떨어지고
있었다. `--ink-1` 로 고쳤다.

**검증**: pytest 전량 통과(이 변경으로 +8건), 프로브 `estimateTwoBlocks` 46측정 신설 +
`estimateCalc`·`estimateScenario` 갱신. 실브라우저 손계산 대조 — 시가 국내채권 직접
3.63 → 2.54(−4.2×0.26%) · 장부가 해외채권 2.42 → 2.33(100% 헤지라 환 0, 스왑 MTM −0.09) ·
해외주식 10.43 → 1.99(0% 헤지라 환 −8.14 전부 노출) · 대체투자 4.84 승계. 시장지표에서

### 7.13 화면 산문 접기 — 답·경고만 보이고 설명은 클릭 뒤로 (2026-08-21 사용자 지시)

**지시**: "지금 화면에 전반적으로 불필요한 글자들이 너무 많아. 관련 내용을 마우스 커서
올리거나 클릭하면 보여주는 식으로 화면 구성을 심플하게 바꿔줘."

**설계 — 무엇이 접히고 무엇이 남나.** 이 저장소의 화면 산문에는 성격이 다른 두 종류가
섞여 있었다: ① 없으면 판단이 틀어지는 것(경고·사유·관측일·구속 ⚠·폴백 이유) ②
궁금할 때만 보면 되는 것(방법론 해설·산식 풀이·사용법·규약 배경). **①은 그대로 두고
②만 접는다** — 접힌 정보는 없는 정보라, ①을 접으면 §7.7.17(구속 귀속)·§7.8.1(묵은
자동값)·「조용한 대체 금지」가 전부 무력화된다. 판정 규칙은 CLAUDE.md 「§7.13 산문
접기」가 정본이다.

**구현** — `app.js` `explainBox(id, [{label}], ...children)` 하나:
- `details.explain` + 「ⓘ 설명」 요약(라벨 지정 가능 — 「표 읽는 법」「이 숫자는 어디서
  왔나」처럼 제목이 곧 내용인 자리). CSS 는 `style.css` `details.explain`/`.explain-body`.
- **토글은 코드가 직접 연다**(preventDefault + open 속성 반전). DOM 셰이드에는 details
  네이티브 토글이 없어서, 기본 동작에 기대면 프로브가 동작을 실행으로 못 잰다.
  index.html 의 정적 접이식(섹션 안내문 10곳)만 재렌더가 없어 네이티브로 둔다.
- **열림 상태는 `EXPLAIN_OPEN`(세션 메모리) 에 id 로 남는다** — recalc 가 DOM 을 통째로
  다시 만들므로, 이게 없으면 슬라이더를 끌 때마다 열어 둔 설명이 닫힌다(실브라우저로
  열기→드래그→열림 유지 확인). localStorage 에는 넣지 않는다 — 새로 열면 접힌 기본값.
- 짧은 힌트 두 곳(기간 필터·환헤지 시뮬레이터 버튼)만 `title`(호버)로 옮겼다 —
  **테스트가 참조하는 문자열은 title 로 옮기지 말 것**(textContent 에서 사라진다).
  접힌 details 는 textContent 에 남으므로 기존 문자열 검사 전제가 유지된다.

**적용 범위**: app.js 접이식 30곳(자산배분 15 · 환헤지 12 · 추정 2 · 리스크·관계분석 등)
+ index.html 정적 10곳. 실브라우저 실측(기본 렌더에서 보이는 글자 수):
자산배분 5,263 → 3,284 (−38%) · 환헤지 3,671 → 2,306 (−37%) · 리스크 −15% ·
개요 −11% · 추정 −9%. 남은 것은 숫자·표·경고다(의도).

**같이 고친 것** — 프로브 두 건이 산문 이동으로 깨졌다: `statesCorrPolicy`(상관 정책
문구)와 `riskCorrRendered`(13주 상관 문구)는 문장을 explain 본문에 원문 유지로 되살려
해결했다 — 문구를 지운 게 아니라 옮긴 것이므로 검사도 그대로 성립해야 맞다.

**검증**: 프로브 `explainFold` 19측정 신설 — 기본 닫힘·클릭 토글·재렌더 열림 유지·
닫힌 본문의 가시 텍스트 제외·**구속 ⚠ 가 보이는 텍스트에 남음**(밴드를 눌러 강제)·
폴백 사유 가시·계약 문자열 textContent 보존. `visText()`(닫힌 explain 본문을 제외한
보이는 텍스트 계산기)가 프로브에 생겼다 — 「화면이 적는다」와 「화면에 보인다」를

  ③ 리스크 등급 밴드를 과거 위기 국면 매칭으로 재설정
- 챔피언 모델의 전망치가 환헤지·자산배분의 기본 가정으로 주입되고, 화면에는 항상
  **"이 기대수익은 모델 X, 최근 5년 적중률 N%"** 출처가 붙는다.

## 9. 알아두면 시간 아끼는 것들

- **테스트가 있다** (다른 세션이 추가, 현재 438개 통과 / 약 6분). `python -m pytest` —
  합성 픽스처(`tests/synth.py`)로 돌아서 **비공개 데이터 없이 실행된다.**
  코드를 고치면 이걸 먼저 돌릴 것. CI도 `test → build(+게이트) → deploy` 순서다.
- **배포 게이트가 있다** (`pipeline/check_output.py`). `process.py` 는 risk/hedge 실패를
  try/except 로 삼키고 exit 0 으로 끝나므로, 이 게이트가 없으면 섹션이 빠진 대시보드가
  초록불로 배포된다. JSON 16개 계약은 세 곳(`process.payloads`·`app.js FILES`·
  `check_output.EXPECTED`)에 적혀 있고 `tests/test_contract.py` 가 불일치를 잡는다.
- **요인 정의는 `risk.derive_inputs()` + `risk.factor_specs()`** 로 모듈 수준에 나와 있다.
  `research/wf_validation.py` 가 **같은 정의를 import** 하므로, 요인을 고치면 배포 코드와
  검증 하네스가 함께 바뀐다(예전처럼 양쪽에 따로 적어 두면 조용히 갈라진다).
- **결측·이상치 검증이 약하다.** 신선도는 시리즈 *끝*만 본다. 단일일 스파이크 필터는
  `hedge.py` `despike()`에만 있다(유로 2005-04-29 ×100 오류, 위안 2008-05-30 오류를 실제로 잡음).
  → 파이프라인 공통 규칙으로 올리는 것이 백로그.
- **`AIs` 저장소**(검증 패널 에이전트 정의)는 이 코드와 런타임 의존이 없다.
- **다른 세션이 같은 브랜치에 PR을 머지한다** (실제로 여러 번 발생: `CLAUDE.md`·의존성 고정,
  공용 산식 통합 + 테스트 + 배포 게이트). **푸시 전 반드시 `git fetch` → 리베이스**하고,
  리팩터링으로 함수 위치가 바뀌었을 수 있으니 작업 시작 전에 최신 코드를 확인할 것.
- 사용자는 GitHub 설정을 **웹 UI에서만** 한다. 토큰·시크릿·Pages 안내는 `docs/SETUP.md`.
- 제 샌드박스에서는 `github.io` 접속이 차단된다. 배포 확인은 Actions API로 하고,
  최종 화면 확인은 사용자에게 부탁한다.
